# PR Reviewer

## Что это

Фоновое код-ревью открытых PR в Bitbucket Cloud тремя моделями (Claude, Codex, Cursor) с приложением в трее для macOS и Windows. Сервис на Node (`src/`) с локальным HTTP API `127.0.0.1:8765`, приложение — Tauri 2 (`app/`). Подробнее — `README.md`.

## Правила для всех ролей

**Публичность.** Репозиторий `AVor0n/ai-review` публичный. В коде, файлах, коммитах, issues и комментариях нет имени клиента и его данных: рабочие репозитории — `frontend`, `backend`, `android`, ключи задач — `PROJ-1234`. Личные данные автора можно.

**Настройки.** Имена проектов — только в настройках. Email, пути, репозитории и токены — только в `config.json` (он в `.gitignore`) и Keychain. Живой `config.json` руками не правим: умолчания — в коде и `schema/`.

**Git.**
- Автор коммитов — локальный `git config user.name/user.email` репозитория. Не задан — спросить пользователя; адрес не угадывать.
- Сообщения на английском, номер задачи в конце в скобках: `fix: restore thread bubble icons (#55)`. Никогда `fix: #55` и `fixes #55`: коммиты идут прямо в `main`, и GitHub закрыл бы задачу до проверки. Закрывает задачи PM.
- После каждого коммита или влития в `main` — сразу `git push origin main`. Ветки задач не пушим.
- Перед коммитом, который меняет `src/`, — `npm test`; меняет `app/` — тесты приложения.

**Установка.** `./install.sh --app-only` можно без разрешения, упомянуть в отчёте. Полная `./install.sh`, force-push, Homebrew, выпуск релиза — только если пользователь разрешил прямо в этой сессии; разрешение, переданное через другую роль, не считается.

**Лицензии.** PNG-рендеры SF Symbols в репозиторий не кладём: лицензия Apple не разрешает их распространять.

**Общение с пользователем.**
- Перед вопросом — выводы и варианты текстом в ответе, сам вопрос с вариантами — в конце сообщения: пользователь часто сидит через Remote Control и не видит кнопок.
- Telegram — если у пользователя есть `~/.local/bin/tg-send`: `tg-send "текст"` (Bash без песочницы), только если пользователь, скорее всего, отошёл и нужен: готов долгий результат, нужно его решение, работа встала. По-русски, 1–3 строки, первым словом «PR Reviewer <роль>:». Без кода, логов, содержимого файлов и данных. Токены в Keychain не читать.

**Где данные.** Данные сервиса — `~/Library/Application Support/pr-reviewer/`, служебные копии и рабочие папки — `~/.pr-reviewer/`.

## Как устроена работа

Над PR Reviewer работают связанные сессии Claude Code по ролям: продукт-менеджер, разработчик, дизайнер, тестировщик. Задачи — issues в `AVor0n/ai-review` на доске https://github.com/users/AVor0n/projects/10.

В корне — только код и сборка. Всё, что пишут и читают роли, — в `agents/`:

- `roles/` — таблица сессий, маршруты и файлы ролей;
- `backlog.md` — правила доски;
- `specs/` — спецификации PM;
- `design/` — макеты, спецификации экранов и дизайн-система `web/`, из которой приложение берёт стили и значки (это часть сборки);
- `bugs/` — отчёты qa;
- `archive/` — бэклог до перехода на доску.

## Кто я

На первом сообщении сессии (в том числе после `/clear`) определи свою роль:

1. Вызови `mcp__ccd_session_mgmt__get_session` с `session_id: "self"` и возьми `sessionId`.
2. Найди его в локальной таблице `agents/roles/sessions.local.md` (её нет в git, см. раздел «Сессии» в `agents/roles/README.md`).
3. Нашёл — прочти `agents/roles/README.md` и файл своей роли, продолжай с раздела «В работе». Пользователю одной строкой: какая роль и что следующее.
4. Не нашёл или файла нет — значит, сессия новая или это другая машина. Если пользователь сам назвал роль («ты дизайнер») — роль из его слов, иначе спроси. Затем допиши свою строку в `sessions.local.md` (нет файла — создай).
