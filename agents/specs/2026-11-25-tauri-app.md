# B-30. Этап 3: приложение в трее на Tauri для macOS и Windows

Автор — PM, 25.11. Основа: B-27 (`agents/specs/2026-11-25-cross-platform.md`, Q23–Q27) и B-29 (`agents/specs/2026-11-25-local-api.md`). Пользователь дал старт 25.11.

## Цель

Одно приложение в трее для macOS и Windows. Оно заменяет окно SwiftUI (`menubar/`) и работает только через локальный API сервиса. Визуальное направление прежнее: iOS-стиль в поповере, клавиатура и доступность вне рамок (правило проекта). SwiftUI живёт до этапа 4 и не меняется.

## Что должно уметь приложение (всё, что умеет SwiftUI)

Экраны: поповер (обзор PR по репозиториям, лимиты, баннеры, запуск, пауза), статистика, память (правила, разбор, история), бэклог находок, архитектурное ревью, доработка, QA, настройки, журнал. Меню по правому клику на значке (B-15). Значок с состояниями и вращением во время прохода (B-21). Системные уведомления с паузой уведомлений (`Alerts.swift`). Снимок картинкой (B-25). Список экранов SwiftUI — `menubar/*.swift`.

## Решения PM

1. **Порядок.** Первая поставка — каркас и поповер: значок, поповер, меню по правому клику, уведомления, автозапуск, связь с API. Дальше экраны по одному: статистика → память → архитектурное ревью → доработка → QA → бэклог → настройки → журнал. Каждый экран — отдельная задача в таблице, её ставит designer после согласования макета с пользователем.
2. **Дизайн-система в вебе.** Designer переносит `Theme.swift` и правила iOS-стиля в токены CSS (цвета светлой и тёмной темы, шрифты, отступы, радиусы, тени) и набор компонентов: строка PR, значки моделей, плитки, баннеры, сегменты, фильтры. Макеты — сразу HTML/CSS на этих токенах, чтобы dev брал их, а не перерисовывал. Тема следует системной.
3. **Код.** TypeScript. Клиент API и типы генерируются из `schema/api.openapi.json`, руками не пишутся. Фреймворк интерфейса выбирает dev, главный критерий — агентам удобно поддерживать.
4. **Связь с сервисом.** Адрес `127.0.0.1:8765` (порт из настроек). Токен: на macOS — из каталога данных сервиса, на Windows — из WSL через `wsl.exe`. Если сервис не отвечает, приложение показывает баннер «Сервис не запущен» с подсказкой, а не пустой экран. Обновления берёт из `/events`, по таймеру API не опрашивает.
5. **Трей на двух системах.** macOS — значок в строке меню, поповер под значком. Windows — значок в области уведомлений, поповер над значком у панели задач. Левый клик открывает поповер, правый — меню. Автозапуск при входе в систему на обеих.
6. **Сборка.** Сборки для macOS и Windows делает GitHub Actions в `AVor0n/pr-reviewer` по тегу или вручную. На macOS `install.sh` по-прежнему собирает и ставит приложение локально. Подпись и нотаризация — вне рамок: пользователь ставит себе сам. После первой успешной сборки workflow `app` выключается (`gh workflow disable`), чтобы не тратить лимиты Actions. Включаем снова, когда переезд на Tauri закончится и активная разработка утихнет (решение пользователя 26.11). До этого приложение на Mac собирает `install.sh`, на Windows — по запросу пользователя.
7. **Проверка.** Поповер и уведомления пользователь проверяет на Mac и на Windows. qa проверяет поведение на копии данных через API (тот же порядок, что для окна SwiftUI). Мелкие визуальные правки — по коду (правило проекта).

## Первая поставка (B-30)

- designer: токены CSS, компоненты, макет поповера и меню значка в HTML, согласование с пользователем, затем задача dev.
- dev, параллельно с дизайном: каркас Tauri 2, значок в трее, пустой поповер, меню, автозапуск, токен и клиент API из OpenAPI, баннер «сервис не запущен», системные уведомления, сборка в GitHub Actions для macOS и Windows. После макета — поповер по макету.
- Неперенесённые экраны (решение PM по вопросу designer, 25.11): все сегменты поповера на месте, а неперенесённые экраны и кнопки, которые к ним ведут, открывают заглушку. На macOS заглушка отсылает к старому окну. На Windows — к команде CLI в WSL для этого экрана (для токенов — `pr-reviewer secret set`). Раскладка от поставки к поставке не меняется. Исключение (Q49, 26.11, #52): журнал становится разделом «Настроек», а не отдельной вкладкой. Статистику под кнопку на «Обзоре» и переименование «Обзор» → «Ревью» делаем позже, вместе с «Мониторингом» (#51, после этапа 4).
- Готово, когда пользователь пользуется новым поповером на Mac и на Windows вместо старого и не теряет ничего из поповера SwiftUI.
