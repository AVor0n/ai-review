# B-29. Этап 2: локальный HTTP API сервиса

Автор — PM, 25.11. Основа: спецификация B-27 (`agents/specs/2026-11-25-cross-platform.md`), решения Q23–Q27. Пользователь дал старт 25.11.

## Зачем

Приложение в трее на Tauri (B-30) должно работать одинаково на macOS и на Windows, где сервис живёт в WSL2. Поэтому окно не читает файлы данных и не вызывает CLI. Всё, что ему нужно, оно получает через локальный HTTP API сервиса (Q24).

## Что сейчас нужно окну

Окно SwiftUI (`menubar/Model.swift`, `Paths`) читает около 25 файлов данных: `status.json`, `state.json`, `prs/`, `stats.jsonl`, `outcomes.jsonl`, `skips.jsonl`, `spend.jsonl`, `limits.json`, состояния и журналы доработки, архитектурного ревью и QA, бэклог, память и её разбор, `config.json`, журнал воркера, пауза и признаки жизни. Ещё оно вызывает около 35 команд CLI: запуск прохода и ревью, доработка, архитектура, QA, память, бэклог, репозитории, модели, пауза, остановка. API должен покрыть всё это. Чего нет в API, того не будет и в новом приложении.

## Решения PM

1. **Отдельный постоянный процесс.** Проход ревью и сейчас запускается раз в минуту (launchd `StartInterval`, systemd timer), а API должен работать всё время. Поэтому сервер API — свой агент: launchd `KeepAlive` на macOS, systemd user service с `Restart=on-failure` на Linux. Ставит и убирает его `install.sh`/`uninstall.sh`. Сервер сам ревью не делает: он отдаёт данные и запускает те же команды, что и окно сейчас.
2. **Без второй логики.** Чтение — через те же модули `src/`, которыми пользуется CLI. Действия — через те же функции, что у команд CLI, или через вызов самого CLI. Правила вроде «прервать только этот PR» (BUG-005/017) должны остаться в одном месте.
3. **Только эта машина.** Сервер слушает `127.0.0.1`. Порт по умолчанию задан в коде (например, 8765) и меняется в `config.json`. Каждый запрос несёт токен (`Authorization: Bearer`). Токен создаётся при установке и лежит в файле с правами `600` в каталоге данных. Приложение читает его оттуда: на Windows через WSL, путь даёт сервис. CORS — только для источника приложения Tauri.
4. **Секреты не отдаются никогда.** Есть «какой секрет задан» и «записать секрет» (только запись). Значения не уходят ни в ответах, ни в журнале.
5. **Изменения — потоком событий.** `GET /events` по SSE: смена статуса прохода, ход модели (как сейчас строка «что делает модель»), смена состояний доработки, архитектуры, QA и бэклога, обновление снимков PR и лимитов. Источник — изменения файлов данных, чтобы не трогать воркеры. Приложение после события перечитывает нужный ресурс.
6. **Описание API — файл `schema/api.openapi.json`.** По нему агенты пишут приложение на этапе 3, его же проверяют тесты.
7. **Настройки.** `GET/PUT /config` с проверкой по `schema/config.schema.json`. Правку пишет сервис, а не человек руками (правило «живой `config.json` руками не правим» остаётся).
8. **Ошибки — понятным текстом по-русски,** как сейчас в CLI. Например, «Сейчас идёт ревью — запустите, когда оно закончится».
9. **SwiftUI на API не переводим:** он доживает до удаления на файлах. Двойной работы нет.

## Что сделать (dev)

1. Сервер API: процесс, агент launchd/systemd, токен, `127.0.0.1`, CORS, `/health` с версией сервиса и признаками жизни воркера.
2. Ресурсы для чтения: всё из раздела «Что сейчас нужно окну». Длинные журналы — с фильтром по периоду и репозиторию: статистика по 7/30/90 дням не должна тащить весь `stats.jsonl`.
3. Действия: все команды, которые сейчас зовёт окно, плюс `secret status/set`, `data export`.
4. `GET /events` (SSE).
5. `schema/api.openapi.json`.
6. Тесты в `npm test`: контракт по схеме, отказ без токена, отказ не с `127.0.0.1`, секреты не попадают в ответы, событие приходит после изменения файла.
7. README — коротко: как работает API и где лежит токен.

## Проверка

- `npm test` на Mac и в Docker Ubuntu с systemd.
- qa на копии данных: ресурсы сходятся с тем, что показывает окно SwiftUI, действия делают то же, что кнопки окна, прерывание затрагивает только выбранный PR.
- Полная `./install.sh` на Mac нужна для нового агента. Только с разрешения пользователя (спросить через `tg-send`, если его нет в сессии).
