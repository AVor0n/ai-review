# Бэклог PR Reviewer

Ведёт PM. Новая идея попадает во «Входящие»; после обсуждения с пользователем (grilling) переходит в «Согласовано» с решением и критериями готовности, затем уходит разработчику.

Статусы: `входящее` → `обсуждаем` → `согласовано` → `в работе (dev)` → `готово` / `отклонено`.

## Правила процесса

- Баг из `product/bugs/` правится только с одобрения пользователя. Порядок: qa → PM → пользователь → PM ставит задачу dev. Если PM передаёт задачу с одобрением пользователя, dev берёт её без отдельного подтверждения (правило от 2026-10-30). Вердикт одного qa или решение PM без одобрения пользователя недостаточны.
- Экранная проверка нужна только для сложных задач. Мелкие визуальные правки designer сверяет по коду, на экране их смотрит пользователь и сам сообщает о проблемах (решение пользователя 2026-10-30).
- Визуальное направление — iOS-стиль, всё приложение живёт в поповере из строки меню. Клавиатура и доступность вне рамок: приложением управляют мышью. Отдельные UX-принципы macOS можно предлагать, но только после обсуждения с пользователем.

## Продуктовый контекст

- Сейчас приложение целиком работает на ноутбуке пользователя, и ноутбук входит в CI-процесс компании. Если пользователь уйдёт из компании, приложение передадут компании, и оно будет работать от имени другого разработчика или системного аккаунта. Отсюда правило: название компании и префиксы веток (`project`, `PROJ-`) хардкодить можно, а личные данные (email, пути, репозитории, токены) задаются только через `config.json` (он в `.gitignore`) и Keychain. Метка launchd `com.avoronin.pr-reviewer` остаётся (решение от 2026-10-30).
- Репозиторий приватный на GitHub, пушит пользователь сам.

### Фича 1: `./install.sh --app-only` — пересборка и перезапуск только приложения

Согласовано с пользователем 2026-10-30 (grilling, два раунда). Идея от qa. Статус: готово (`b3f101b`). qa проверил вживую: пересборка за 46 с, приложение перезапущено, идущий проход ревью не прервался. Осталось посмотреть строку сборки на экране.

**Зачем.** dev и qa проверяют правки окна сами, без разрешения пользователя. Фоновый воркер и идущее ревью не затрагиваются.

**Поведение.**
1. Проверяет только наличие `swiftc` и то, что полная установка уже делалась (агент `com.avoronin.pr-reviewer.menubar` зарегистрирован). Если её не было, отказывает с подсказкой запустить `./install.sh`. Токены и конфиг не проверяет.
2. Собирает весь бандл: исполняемый файл, иконку, `Info.plist`, подпись. Сборка идёт во временную папку, установленное приложение подменяется только после успешной сборки. Если сборка упала, старое приложение работает дальше, скрипт печатает ошибку компилятора и выходит с ненулевым кодом.
3. При сборке записывает хэш коммита, дату и признак незакоммиченных правок. Внизу вкладки «Настройки» строка вида «Сборка 1c3d57d · 30.10 14:05», с пометкой, если в сборке есть незакоммиченные правки. Полная установка записывает то же самое.
4. Перезапускает только агент приложения (`launchctl kickstart -k`), даже если пользователь сам из него вышел. Воркер не трогает. Открытый поповер или лист закрывается, несохранённые правки в нём пропадают, и это принято.

**Правила после выпуска.** dev и qa запускают `--app-only` без разрешения пользователя и пишут о каждой пересборке в своём отчёте. Полная `./install.sh` по-прежнему только с разрешения. Предупреждения об устаревшей сборке и уведомлений macOS нет. Support описывает режим в `docs/`.

**Не делаем сейчас.** Предупреждение об устаревшей сборке (пригодится при передаче, отдельная задача). Защита несохранённого черновика при перезапуске.

**Готово, когда:**
- `--app-only` пересобирает и перезапускает приложение, а PID воркера и идущий проход не меняются;
- при сломанной сборке старое приложение остаётся рабочим;
- в настройках видна строка сборки с правильным коммитом;
- qa проверил всё это вживую.

**Очерёдность.** Сначала эта фича, затем правки дизайна B1, A4c и A9: их проверяем уже через `--app-only`.

- **Дизайн: баннеры, пауза, иконка** (одобрено пользователем 2026-10-30, спецификация `product/design/specs/2026-10-30-banners-pause-icon.md`). B1: виден один, самый важный баннер, под ним «Ещё N сообщений». A4c, вариант А: на общей паузе интервал и тумблеры репозиториев заблокированы, внешний вид прежний. A9: иконка без своей плитки, обводки и тени. Плюс официальные значки моделей (одобрено пользователем designer'у, спецификация `product/design/specs/2026-10-30-agent-logos.md`): меняется только форма в `AgentIcons.swift`, цвета прежние, Cursor остаётся бирюзовым. Статус: B1 (`7fac731`), A4c (`f08d259`), A9 (`6554c66`) и значки моделей (`0424d9a`) установлены полной установкой (сборка `aba17b5`). Designer принял на экране A9, значки моделей и строку сборки. ### Зелёная галочка вместо «0», когда модели ничего не нашли

Согласовано с пользователем 2026-10-30. Идея пользователя, вид от designer. Статус: готово (`d4f385c`, docs `4e48525`), установлено через `--app-only`. Dev добавил правило: если фоновых моделей нет вовсе, галочки нет. Designer сверил код со спецификацией. На экране смотрит сам пользователь: по его решению экранная проверка нужна только для сложных задач. Переход «новый коммит → снова 0» вживую не пойман.

**Зачем.** Сейчас счётчик комментариев в строке PR (`OverviewView.swift:484–490`) показывает серый «0» в двух случаях: ревью не было и ревью было, но чистое. Пользователю нужно сразу видеть, что PR в порядке.

**Правила.**
1. Галочка показывается, когда комментариев в PR нет (`threads == 0`) и все модели, которые запускаются в фоне, проверили текущий коммит (состояние `done`). Модели, которые запускаются только вручную, не учитываются.
2. Пришёл новый коммит, и хотя бы одна фоновая модель его ещё не проверила (не было ревью, старый коммит, в очереди, идёт): снова серый «0».
3. Если модели что-то нашли, но в PR не опубликовали (проблема была до PR и ушла в бэклог, редкий P3 отфильтрован), галочка всё равно ставится: в этом PR исправлять нечего.
4. Если в PR есть комментарии (в том числе от людей), счётчик работает как сейчас.

**Вид** (designer). Значок `checkmark.bubble.fill`, `Color.green`, 12 pt, без числа. Подсказка: «Модели проверили последний коммит и замечаний не нашли». Остальные состояния прежние: серый «0» (`.tertiary`), серое число при открытых тредах, зелёный контур `checkmark.bubble` и «N/N», когда все треды закрыты.

**Готово, когда:** в строке чистого PR видна галочка; после нового коммита до ревью снова «0»; при ручной модели без ревью галочка есть; dev проверил через `--app-only`; support дописал состояние в `docs/`.

Раздел удалённого из настроек репозитория остаётся намеренно: после возврата репозитория не будет повторного ревью. Support допишет в `docs/review.md`.
3. **Образы `pr-reviewer-qa-backend:<коммит>`.** Хранится только самый свежий образ. Старые удаляются после успешной сборки нового; образ, который нужен идущему тестированию, не трогается.

Общее: ошибка чистки не роняет основную работу, только запись в журнал. Support обновляет `docs/fix.md`, `docs/data.md`, `docs/review.md`, `docs/qa.md`.
