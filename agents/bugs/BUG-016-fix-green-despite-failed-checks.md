# BUG-016: доработка показывает зелёное «Правок не понадобилось», когда проверки упали

- **Статус:** закрыт
- **Серьёзность:** S3
- **Компонент:** CLI (`src/fix.mjs`), окно (`menubar/FixViews.swift`)
- **Заведён:** 2026-10-30, qa
- **Источник:** техпод при написании docs/, подтверждено qa по коду

## Описание

В `runFix` проверка «ветка не изменилась» стоит раньше проверки упавших проверок. Сценарий: Claude ничего не правит (или ветка уже на свежей базе), `lint`/`ts-check`/`test` падают, починка ничего не меняет. Тогда HEAD равен ожидаемому коммиту, итог — `status: 'nothing'`, «Правок не понадобилось, ветка не изменилась» (или «Ветка уже на свежей <base>»). Обработчик считает `nothing` успехом (`state: 'done'`), окно рисует зелёную галочку. Что проверки падают, видно только в строке «Проверки» внутри отчёта.

## Окружение

- Код после 57f0012. В текущих `fixes/state/*.json` такого случая нет.

## Шаги воспроизведения

С разрешения пользователя (доработка тратит модель и может пушить):

1. PR, у которого на голове падает `yarn ts-check`, а открытые замечания не требуют правок (или rebase-режим на ветке, уже стоящей на свежей базе).
2. «Доработать» / «Rebase».

## Фактический результат

Зелёная галочка, «Правок не понадобилось, ветка не изменилась», в отчёте «Проверки: падают: yarn ts-check».

## Ожидаемый результат

Итог не зелёный: явно сказано, что проверки падают и Claude их не починил.

## Предполагаемое место в коде

- `src/fix.mjs:357-360` — `nothing` возвращается до проверки `failures` (`src/fix.mjs:362`).
- `src/fix.mjs:409` — `ok = pushed || nothing` → `state: 'done'`.
- `menubar/FixViews.swift:71, 182` — `done` рисуется зелёным.
