## Замечания

1. **Событие `config` приходит только на первую правку настроек.** Сервер следит за самим файлом `config.json`, а сервис пишет его через временный файл и переименование. После первой записи наблюдатель смотрит на старый файл, и следующие правки событий не дают. Проверено: после перезапуска сервера две смены интервала подряд — одно событие `config`. Приложение не узнает о смене настроек, сделанной вторым окном, CLI или самим сервисом (например, срок токена). Нужно следить за папкой и фильтровать по имени. S3.
2. **`data export` с относительным путём кладёт архив в папку кода.** CLI запускается сервером с `cwd` = папка репозитория, поэтому `{"file":"x.tar.gz"}` создаёт `~/tools/pr-reviewer/x.tar.gz`. Архив не в `.gitignore` и легко уедет в коммит, а в нём `config.json` и вся память. Без `file` — то же самое. S3.
3. **`PUT /secrets/{id}` с неизвестным id и без `value` отвечает «Нужно поле value»,** а не «Нет секрета nope». Мелочь. S4.
   - **Пользователь 25.11: чинить замечания 1–3.** Переданы dev, после правки — перепроверка qa на той же копии.
4. **На живой машине уже есть `api-token` (25.11 18:37).** Его создал прогон dev до установки агента. Не ошибка, просто учесть: при полной установке токен останется тот же.

Не проверено: работа агента launchd на Mac (нужна полная `./install.sh`, только с разрешения пользователя), запись секрета через API в Keychain, `memory learn`/`review`, задания бэклога, `repo add/clone/remove`, обновление лимитов и моделей Cursor (сеть и модели). Это те же команды CLI, сервер только передаёт аргументы.
