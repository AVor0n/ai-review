# BUG-015: «Прервать» обычного ревью не срабатывает во время синхронного git

- **Статус:** закрыт
- **Серьёзность:** S3
- **Компонент:** CLI (`src/cli.mjs`, `src/git.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** замечание dev при исправлении BUG-006, подтверждено qa по коду

## Описание

То же, что BUG-006, но для фонового прохода. `stop` (кнопка «Прервать» в обзоре, баннер зависшего прохода, `pause`) шлёт SIGTERM только процессу сервиса (`process.kill(pid)`). Git в сервисе синхронный (`execFileSync`/`spawnSync`), поэтому `abort` срабатывает только после конца git-команды: `fetch` — до 10 мин, `clone` — до 30 мин, локальные команды без таймаута. README обещает: в баннере зависания «"Прервать" остановит этот проход», а баннер появляется, когда процесс заблокирован синхронным git больше 15 минут, то есть именно когда «Прервать» не работает. CLI при этом сразу пишет «Остановлен запуск <pid>».

## Окружение

- Сервис активен, Node v22.23.1, macOS 27.0.1.

## Шаги воспроизведения

Механизм воспроизведён изолированно, см. BUG-006 (`scratchpad/sigterm-sync.mjs`): SIGTERM, посланный на 1-й секунде `execFileSync('sleep 6')`, обработан только на 6-й.

В живом сервисе — только с разрешения пользователя, нужна зависшая сеть:

1. Во время `git fetch` или `clone` служебного клона отключить сеть так, чтобы соединение повисло.
2. Нажать «Прервать» в обзоре.

## Фактический результат

Проход продолжается до таймаута git (10–30 мин). `worker.pid` жив, пульс стоит.

## Ожидаемый результат

Проход прерывается за секунды: git убит, блокировка снята, статус «ревью прервано».

## Предполагаемое место в коде

- `src/cli.mjs:566-571` — `stop` шлёт сигнал только pid. Нужна группа процессов, как в BUG-006 (`requestStop` из `src/store.mjs`). Проверить, что launchd-воркер — лидер своей группы; иначе сигнал группе заденет чужие процессы, и придётся убивать дочерний git по pid.
- `src/git.mjs:19-20` — `execFileSync` с таймаутами 10/30 мин.
- `src/cli.mjs:117-123` — `abort`.
- `menubar/Model.swift:1438-1443` — окно вызывает `stop`; через `pause` (`setServicePaused`) — тот же путь.
