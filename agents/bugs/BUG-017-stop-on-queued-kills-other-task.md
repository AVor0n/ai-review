# BUG-017: «Прервать» у PR в очереди прерывает текущую задачу другого PR

- **Статус:** закрыт
- **Серьёзность:** S3
- **Компонент:** окно (`menubar/Model.swift`, `FixViews.swift`, `ArchViews.swift`), CLI (`src/fix.mjs`, `src/arch.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** техпод при написании docs/, подтверждено qa по коду. Связан с BUG-005

## Описание

В листах доработки и архитектурного ревью кнопка «Прервать» показывается, когда задача активна, а активной считается и `queued` (`isActive: state == "queued" || state == "running"`). Кнопка вызывает `fix stop` / `arch stop`, а они убивают обработчик целиком, то есть ту задачу, которая выполняется сейчас, у другого PR. Сама заявка этого PR остаётся в очереди (BUG-005). Человек хотел отменить ожидание у PR B, а оборвал идущую доработку PR A.

## Шаги воспроизведения

С разрешения пользователя (доработка тратит модель):

1. Поставить доработку PR A, следом — PR B.
2. Открыть отчёт доработки PR B (часы «в очереди»), нажать «Прервать».

## Фактический результат

PR A — «доработка прервана», PR B — по-прежнему «в очереди».

## Ожидаемый результат

«Прервать» у заявки в очереди снимает только эту заявку, а у PR A работа продолжается. Как вариант — у заявки в очереди кнопка «Отменить» вместо «Прервать».

## Решение пользователя (2026-10-30)

«Прервать» у PR отменяет задачу только этого PR — идущую или ждущую в очереди; заявки других PR продолжают выполняться. Это ожидаемый результат для BUG-005 и BUG-017.

## Предполагаемое место в коде

- `menubar/Model.swift:634, 699` — `isActive` включает `queued`.
- `menubar/FixViews.swift:152`, `menubar/ArchViews.swift:165` — кнопка «Прервать» по `isActive`.
- `src/fix.mjs:55-59`, `src/arch.mjs:61-65` — `stop` без указания PR.

Стоп у ждущего B → `true`, файл B снят, B «доработка прервана», A идёт, обработчик жив. Стоп у PR без задачи → `false`. Стоп у идущего A → A «доработка прервана», старый обработчик завершён, сразу запущен новый `cli.mjs fix-worker`, заявка C осталась ему. Прогнано в двух вариантах: обработчик не лидер группы (сигнал по pid) и лидер группы, как у сервиса; во втором новый обработчик сигнал группы не получил. Дальше в песочнице новый обработчик остановился на чтении токена Keychain — это ограничение HOME песочницы, не правки. arch и qa по коду устроены так же, отдельно не гонял. `swiftc -typecheck` без ошибок; кнопки в окне проверю после переустановки. Узкое место dev (задача A закончилась между проверкой состояния и сигналом) не воспроизводил
