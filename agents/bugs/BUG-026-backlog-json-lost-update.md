# BUG-026: несколько процессов переписывают backlog.json целиком без блокировки

- **Статус:** отложен
- **Серьёзность:** S4
- **Компонент:** CLI (`src/backlog.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** техпод при написании docs/, подтверждено qa по коду

## Описание

Каждое изменение бэклога читает `backlog.json`, меняет запись и записывает файл целиком. Одновременно это могут делать проход ревью (`addToBacklog`), фоновый разбор (`setBacklogTriage` на каждую запись) и команды окна (`filed`/`drop`/`reopen`, отдельными процессами). Если две записи пересекутся, изменение одной потеряется: например, вердикт разбора или «Задача заведена». Окно между чтением и записью узкое (миллисекунды), поэтому вероятность небольшая. Комментарий у `close-stale` (`src/cli.mjs:509`) показывает, что с параллельными `drop` из окна это уже случалось.

## Шаги воспроизведения

Детерминированно не воспроизводится. Изолированно: на копии данных запустить параллельно 10 `backlog drop` по разным записям, затем посчитать отклонённые.

## Ожидаемый результат

Ни одно изменение не теряется: файловая блокировка вокруг чтения и записи или запись через один процесс.
