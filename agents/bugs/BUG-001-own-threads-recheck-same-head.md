# BUG-001: модель повторно и платно перепроверяет свои только что опубликованные треды на той же голове

- **Статус:** закрыт
- **Серьёзность:** S4
- **Компонент:** CLI (`src/review.mjs`, `src/comments.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa по коду и данным

## Описание

После ревью с находками на следующем проходе та же модель запускается ещё раз в роли `replies` на той же голове PR, хотя ответов ждать не от кого (`ответов: 0`) и люди в тредах не писали. Модель перепроверяет свои только что опубликованные замечания. По README («Экономия») свои треды перепроверяются только на новой голове или после нового ответа человека; комментарий в `src/review.mjs:430` говорит то же.

## Окружение

- Сервис активен (не на паузе), Node v22.23.1, macOS 27.0.1
- Наблюдается во всех репозиториях, у всех трёх моделей

## Шаги воспроизведения

1. Модель A ревьюит PR на голове H и публикует хотя бы одно замечание.
2. В PR ничего не меняется: ни новых коммитов, ни ответов людей.
3. Следующий проход.

## Фактический результат

Модель A стартует `(replies, ответов: 0)` на той же голове H и ничего не публикует.

## Ожидаемый результат

Пустого запуска нет: свои новые треды считаются проверенными на голове H.

## Логи и доказательства

`worker.log`, 29.10, frontend#2795:

```

18:35:46 codex: старт (second, ответов: 1)

18:38:19 claude: старт (replies, ответов: 0)      ← голова та же a66eb5f68509
18:38:37 claude: готово — {"P0":0,"P1":0,"P2":0,"P3":0}, ответов 0
```

То же 28.10 в backend#2059 (claude, 11:02 → 11:10).

Сверка `worker.log` и `stats.jsonl` с 18.10: 33 запуска `replies` с `ответов: 0` на той же голове сразу после ревью той же модели с находками, без закрытых тредов. По тарифам API это около $7.92.

## Предполагаемое место в коде

- `src/review.mjs:431-434` — `ownChecks` пишется только для `own` (тредов, которые были до запуска). Треды, которые модель опубликовала в этом запуске, туда не попадают.
- `src/comments.mjs:34` — тред без записи в `checks` (`!checked`) считается требующим проверки.
- `src/review.mjs:441` — `commentCount = null` не даёт проходу отсечь PR по числу комментариев.

Вероятное исправление: после публикации записать в `ownChecks[agentId]` id новых корней (`outcome.tracked[].commentId` и опубликованные без трекинга) с `head` и `lastHumanReply: 0`.
