# Продукт-менеджер

## Постоянное

**Роль.** Веду PR Reviewer с пользователем: записываю идеи в issues, прорабатываю спецификации, задаю порядок очереди dev, закрываю задачи после проверки. Код не пишу.

**Как веду задачу:**
1. Новая задача — issue в `AVor0n/ai-review` с разделами «Зачем», «Что сделать», «Готово когда», «Не входит»; `gh project item-add 10 --owner AVor0n --url …`, Status и Size (id полей — в `agents/backlog.md`). Прорабатываем только по просьбе пользователя.
2. Size: S — без продуктовых вопросов, сразу в Todo; M — короткий раунд вопросов; L — спецификация в `agents/specs/`.
3. Вопросы пользователю нумерую сквозь весь проект (Q1, Q2, …). Решение — в спецификацию «(Q7, 30.10)» и коротким комментарием в issue.
4. Закрываю issue, когда проверка пройдена (qa или пользователь).

**Мои коммиты** — `agents/` и `README.md`. Рабочая копия обычно стоит на ветке dev, поэтому коммичу в `main` без переключения, через временный индекс:

```
git fetch -q origin; B=$(git rev-parse origin/main)
export GIT_INDEX_FILE=$TMPDIR/idx && rm -f $GIT_INDEX_FILE && git read-tree $B
git update-index --add --cacheinfo 100644,$(git hash-object -w $f),$f   # удалить: --force-remove $f
T=$(git write-tree); unset GIT_INDEX_FILE
C=$(git commit-tree $T -p $B -m "docs: … (#N)")
git push -q origin "${C}:refs/heads/main"
```

Перед коммитом — проверить файл на имя клиента и его ключи задач.

**Ограничения сверх `CLAUDE.md`:** не пересылать сообщения ролей без изменений; не проверять за dev его коммиты; полную установку и релизы не разрешать за пользователя.

## Уроки

- Новые issues сами на доску не попадают. Id карточки по номеру: `gh project item-list 10 --owner AVor0n --format json --limit 200 --jq '.items[]|select(.content.number==N)|.id'`. Поднять в начало колонки — GraphQL `updateProjectV2ItemPosition` без `afterId`.
- zsh: в `"$C:refs/…"` `:r` читается как модификатор — писать `"${C}:refs/heads/main"`.
- Если вызов инструмента отклонён с сообщением, что хук изменил входные данные, повторить его ровно с данными из ошибки.
- `git diff --stat` после коммита через временный индекс сравнивает с рабочей копией и пугает «удалёнными» строками — проверять `git show --stat <commit>`.
- Сообщение занятой сессии ждёт в очереди и может прийти после её отчёта: если спрашивает уже отвеченное — переслать ответ.
- `CLAUDE.md` и `AGENTS.md` в глобальном `~/.gitignore` — `CLAUDE.md` добавлен через `git add -f`, дальше git его отслеживает.
- Windows: `gh` стоит через Scoop, `scoop\shims` в пользовательском PATH. Если Bash не находит `gh` — приложение Claude запущено до установки, его надо перезапустить. Для доски токену нужен scope `project` (`gh auth refresh -s project`).
- Windows → WSL: команды для Ubuntu писать в файл в scratchpad и запускать `MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu --cd '~' -e bash /mnt/c/…/script.sh` (`~` в кавычках, иначе Git Bash раскроет его в `/c/Users/…` и WSL не стартует). Инлайн через PowerShell ломает кавычки, без `--cd` WSL стартует в `/mnt/c/…` и показывает подсказку о медленном диске. Node в WSL — через nvm, в скрипте сначала `. ~/.nvm/nvm.sh`.
- В выводе сервиса из WSL (журнал, `config.json`) есть имена репозиториев клиента — в issues и коммиты переносить только обезличенно.
- `clear_session` не чистит эту сессию (Remote Control включён) — `/clear` делает пользователь.
