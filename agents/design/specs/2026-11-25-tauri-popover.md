# Спецификация: поповер в приложении Tauri (B-30)

Дата: 26.11.2026, дизайнер. Одобрено пользователем 26.11.2026 («Одобряю»).
Макет: `agents/design/mockups/2026-11-25-tauri-popover.html`, каталог компонентов: `agents/design/mockups/2026-11-25-web-components.html`.
Продуктовая спецификация: `agents/specs/2026-11-25-tauri-app.md`, кроссплатформенность: `agents/specs/2026-11-25-cross-platform.md`.

## Главное

Поповер переносится из SwiftUI без изменений: сегменты, строка статуса, баннеры, секции репозиториев, строки PR. Источник правды для вёрстки — HTML макета и стили `agents/design/web/`:

- `tokens.css` — цвета светлой и тёмной темы, шрифты, размеры текста, отступы, радиусы, тени, длительности;
- `components.css` — классы компонентов;
- `icons.svg` — спрайт иконок Phosphor 2.1.1 (MIT) и нескольких своих, у каждого символа в комментарии SF Symbol, который он заменяет;
- `logos/` — знаки моделей.

Разметку брать из шаблонов `<template id="tpl-…">` макета как есть. Стили импортировать из `agents/design/web`, не копировать: правки дизайнера тогда приходят сами. Своих цветов, размеров и отступов в `app/` не заводить. Если чего-то не хватает, написать мне, токен или класс добавлю я.

Что нового по сравнению с SwiftUI:
1. Баннер «Сервис не запущен» и связанные с ним состояния значка и меню (уже сделано в b665f79).
2. Иконки Phosphor вместо SF Symbols.
3. В тексте баннера токена нет слова «Keychain».
4. Заглушки неперенесённых экранов.

## Тема

- По умолчанию тема системная (`prefers-color-scheme`).
- Атрибут `data-theme="light" | "dark"` на `<html>` задаёт её явно. Переключателя в первой поставке нет, атрибут — на будущее.
- Системный акцент не подхватываем: акцент всегда `--accent`.

## Рамка окна

| | macOS | Windows 11 |
|---|---|---|
| Где | под значком в строке меню | над значком у панели задач, на 12 px выше панели |
| Стрелка | 10 px вверху, указывает на значок: `--arrow-x` от левого края поповера до центра значка | нет |
| Класс | `.popover-frame--mac` | `.popover-frame--win` |
| Скругление | 12 | 8, тонкая рамка 1 px |
| Шрифт | SF Pro | Segoe UI Variable — строки чуть шире, это нормально |

Поповер 780×600 на обеих системах, окно прозрачное, тень рисует CSS. Размеры окна с полями под тень — как в 3694b44.

Если значок у края экрана, окно сдвигается внутрь экрана, а стрелка остаётся над значком. `--arrow-x` не меньше 24 и не больше 756.

Закрытие:
- клик мимо поповера;
- повторный клик по значку.

## Состояния шапки

Строка статуса и кнопки в ней — как в SwiftUI (`OverviewView.swift`). На макете три состояния:
- одно ревью;
- фоновое ревью выключено (кнопка «Включить»);
- три ревью сразу (знаки моделей в тексте, полный список в подсказке).

«Сервис не отвечает» сделан в b665f79 и совпадает с макетом. Правила, которые из разметки не видны:

- баннер появляется, если API не ответил дважды подряд (около 5 с), чтобы не мигать при запуске;
- приложение пробует подключиться само; «Проверить снова» — попытка сразу;
- если связь пропала, когда данные уже были, список PR остаётся на месте, а баннер встаёт первым.

## Баннеры

Порядок, тексты и раскрытие «Ещё N сообщения» — как в SwiftUI. Варианты цвета в `components.css`:

| Класс | Цвет | Для чего |
|---|---|---|
| `--critical` | красный | сервис не запущен, токен истёк, память заполнена или переполнена, файл памяти повреждён |
| `--alert` | оранжевый | проход завис, последний проход с ошибкой, не прочитаны данные |
| `--warning` | жёлтая заливка, оранжевая иконка | токен истекает, память почти заполнена |
| `--info` | акцентный | новые правила в памяти |

Таблица исправлена 26.11 по вопросу qa (замечание 8 в `agents/bugs/feature-b30-popover-check.md`): было «токен истекает — `--alert`», а верно `--warning`, как в SwiftUI (`OverviewView.swift`, `tokenBanner`, `memoryBanner`).

Новый текст баннера токена: «Без него … Выпустите новый и сохраните — срок обновится сам.» Слова «Keychain» нет ни на одной системе.

## Секции и строки PR

Паритет с SwiftUI:
- секция репозитория сворачивается;
- знак паузы у репозитория;
- строка PR — значки моделей, название, мета, треды, кнопки доработки, архитектуры, QA, время обновления;
- черновик и устаревший отчёт приглушены (`--dim-opacity`).

Значок модели во время ревью и в очереди крутится (`--spin-period` 2 с), бейдж при этом скрыт. Подсказки — атрибут `title`, тексты те же, что в SwiftUI.

## Меню по правому клику

Меню системное: Tauri собирает пункты, рисует macOS или Windows. Левый клик открывает поповер, правый — меню, на обеих системах.

Состав — как в SwiftUI, спецификация `2026-10-30-status-menu.md`:

1. Серая строка статуса.
2. «Прервать ревью» / «Прервать все ревью» или «Проверить сейчас».
3. Переключатель фонового ревью.
4. Блок уведомлений с подменю «На 1 час … Пока не включу».
5. «Выйти из PR Reviewer» (на Mac с ⌘Q).

Новое: когда сервис не отвечает, первая строка «Сервис не отвечает». Пункты ревью и фонового ревью скрыты, уведомления и «Выйти» остаются.

Значки моделей у строк «Идут 3 ревью» — если Tauri рисует иконку у неактивного пункта. Если нет, остаётся текст: модель в нём уже названа.

## Значок в трее

Значок macOS шаблонный: его красит система, справа число PR без ревью на текущем коммите. На Windows система его не красит. Приложение выбирает белый или чёрный по теме панели задач, а число рисует бейджем в правом нижнем углу.

| Состояние | Значок | Подсказка |
|---|---|---|
| Ожидание | `i-bubble-check` + число | PR Reviewer: ожидание / PR без ревью на текущем коммите: N |
| Идёт ревью | знак модели, вращается | PR Reviewer: ревью frontend #2828 · Claude (первым) |
| Фоновое ревью выключено | `i-pause-fill` | PR Reviewer: пауза |
| Последний проход с ошибкой | `i-bubble-warning`, красный | PR Reviewer: ошибка |
| Проход завис | `i-warning-fill`, оранжевый, мигает 6 с, потом горит ровно | PR Reviewer: проход ревью не продвигается N мин — прервать можно в обзоре |
| Новое: сервис не отвечает | `i-bubble-slash` | PR Reviewer: сервис не отвечает |

Размеры значка на Windows: 16 px при масштабе 100 %, 20 px при 125 %, 24 px при 150 %. Вращение — 20 кадров в секунду. Если для трея это тяжело, хватит 10.

## Заглушки неперенесённых экранов

Решение PM: все сегменты на месте с первой поставки. С 26.11 (Q49, #52) их четыре — «Обзор, Бэклог, Статистика, Настройки»: «Журнал» стал листом в «Настройках». Уже собранный в B-30 пятый сегмент «Журнал» и его заглушку dev убирает в #43, вместе с листом журнала: до этого кнопкам «Журнал» в баннерах больше некуда вести. Неперенесённый экран и кнопки, которые на него ведут, открывают заглушку. Разметка в `tpl-stub-*`, классы `.stub`, `.command-list`, `.command`.

- Иконка `i-clock`, заголовок — название экрана или раздела.
- macOS: «Экран переедет в следующих версиях. Пока он есть в старом окне». Кнопок нет.
- Windows: «Экран переедет в следующих версиях. Пока — через командную строку в WSL». Ниже — список команд для этого экрана, у каждой кнопка «Скопировать» (`i-copy`, подсказка «Скопировать»).

Откуда открывается заглушка и какие команды в ней на Windows — таблица в разделе 6 макета:
- вкладки «Бэклог», «Статистика», «Настройки»;
- «Подключить…»;
- «Обновить…» в баннере токена;
- «Проверить правила» и «Посмотреть» в баннерах памяти;
- кнопки доработки, архитектуры и QA в строке PR, когда они открывают отчёт, ход или лист (решено с dev 26.11).

Сегмент вкладки при этом выбран.

Кнопка «Журнал» в баннерах ведёт не на заглушку: она открывает вкладку «Настройки» и сразу лист журнала (`2026-11-26-tauri-log.md`). Пока лист журнала не сделан (#43), всё остаётся как сейчас: сегмент «Журнал» с заглушкой, кнопка ведёт на неё.

Кнопки строки PR на Windows:

| Кнопка | Заголовок заглушки | Команды |
|---|---|---|
| Доработка | Отчёт доработки | `pr-reviewer status`, `tail -f ~/.local/state/pr-reviewer/worker.log` |
| Архитектура | Архитектурное ревью | `pr-reviewer arch show --repo <slug> --pr <id>` |
| QA | Тестирование PR | `pr-reviewer qa show --repo <slug> --pr <id>` |

Slug и номер подставляются из строки, команду можно скопировать и сразу запустить. Подтверждение запуска по этим кнопкам — системный диалог Tauri, тексты из SwiftUI слово в слово.

Если `install.sh` кладёт в PATH не `pr-reviewer`, а команда вызывается как `bin/pr-reviewer`, подставить тот вид, который реально работает.

## Не проверено, проверить на Windows

- Segoe UI Variable: ширина строк, ничего не обрезается в строке PR и в сегментах.
- Команда `wsl systemctl --user restart pr-reviewer-api` в баннере.
- Положение поповера у панели задач, когда она слева, справа или вверху: поповер встаёт у значка по той же логике, стрелки нет.

## Готово, когда

- Поповер на Mac и Windows в светлой и тёмной теме совпадает с макетом. Проверка — скриншот рядом со страницей макета.
- Все цвета, размеры и иконки — из `agents/design/web`, в `app/` нет захардкоженных значений.
- Меню, значок и подсказки — по таблицам выше, включая состояние «сервис не отвечает».
- Заглушки открываются из всех точек таблицы, команды копируются.
