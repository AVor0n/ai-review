# Спецификация: лист «Память ревьюеров» в приложении Tauri (B-30, экран 2 из 8)

Дата: 26.11.2026, дизайнер. Одобрено пользователем 26.11.2026 («Одобряю»). Его правка — убрать подпись «Срабатывания считаются с … · ревью с учётом: N» — внесена в макет.
Макет: `agents/design/mockups/2026-11-26-tauri-memory.html`.
Источник поведения: `menubar/SettingsView.swift` (`MemorySheet`, `LessonRow`, `LessonEditor`), `menubar/MemoryReviewView.swift`, `menubar/MemoryHistoryView.swift`.

## Главное

Лист переносится без изменений:
- три вкладки «Правила · N», «Разбор», «Что менялось»;
- правка и удаление правил, своё правило снизу;
- разбор с планом «было / станет», журнал с откатом;
- пустая память («Изучить историю репозитория») и повреждённый файл.

Тексты — слово в слово из SwiftUI. Действия — те же команды CLI через API сервиса: `memory review`, `memory restore`, добавление, правка и удаление правила, изучение истории.

Разметка — шаблоны `tpl-sheet-*` макета. Стили из `agents/design/web`:
- лист: `.sheet-backdrop`, `.sheet`, `.sheet__head`, `.sheet__bar`, `.sheet__body`, `.sheet__footer`, `.round-button`;
- поля и кнопки: `.text-field`, `.button--small`;
- карточки и статусы: `.info-card`, `.status-label`, `.hourglass`;
- память: `.lesson*`, `.lesson-editor`, `.plan-*`, `.diff`, `.history-*`;
- новый токен `--purple`, новые иконки — `i-open-external`, `i-edit`, `i-trash`, `i-bolt`, `i-plus`, `i-minus`, `i-merge`, `i-history`, `i-check-circle-fill`.

Классы `.sheet*`, `.text-field`, `.info-card` общие: ими же будут сделаны остальные листы (доработка, архитектура, QA, настройки).

## Что меняется по сравнению с SwiftUI

1. **Где открывается.** Лист встаёт поверх поповера на той вкладке, где нажали кнопку. В SwiftUI окно сначала переключалось на «Настройки».
   - Точки входа сейчас: «Проверить правила» и «Посмотреть» в баннерах памяти. Позже добавится «Память ревьюеров…» в настройках.
   - Заглушка «Память frontend» из первой поставки убирается.
2. **Подписи о начале учёта нет.** Подпись «Срабатывания считаются с … · ревью с учётом: N» справа от вкладок убрана по решению пользователя. Счётчик у каждого правила остаётся.
3. **Подтверждение отката** — системный диалог Tauri. Заголовок «Откатить разбор памяти?», текст из SwiftUI, кнопки «Отмена» и «Откатить» (опасная).
4. **«Открыть в VS Code» на Windows.** Файл памяти лежит в WSL, кнопка открывает его по пути `\\wsl.localhost\<дистрибутив>\…`. Если VS Code не найден, кнопки нет — и в шапке, и в карточке повреждённого файла.

## Лист

- **Подложка.** Затемняет поповер: `rgba(0,0,0,.18)`, в тёмной теме `.45`. Клик по ней закрывает лист.
- **Размер и место.** Ширина 600, отступ сверху 16, по центру. Поля 20, промежутки 12, фон `--bg`, радиус 12.
- **Шапка.**
  - Заголовок «Память ревьюеров · <slug>», под ним подпись из SwiftUI.
  - Справа две круглые кнопки 24: «открыть в редакторе» и «закрыть» (подсказка «Закрыть»).
  - Кнопки «Готово» нет: изменения сохраняются сразу.
- **Вкладки.** Сегменты 110 px.
  - На «Разборе», пока открыта другая вкладка, — бейдж с числом изменений в готовом плане (`.segmented__count`).
  - Во время разбора вкладка называется «Разбор…».
- **Высота тела постоянная,** чтобы лист не прыгал при смене вкладок: «Правила» 300, «Разбор» и «Что менялось» 340. Прокрутка внутри.
- **Открывается сразу на «Разборе»,** если есть готовый план или идёт разбор.
- **Низ листа.** На «Правилах» и «Что менялось» — поле «Своё правило, например: «`formatDate` всегда получает UTC»» и кнопка «Добавить». Пока поле пустое, кнопка неактивна; Enter добавляет. На «Разборе» — кнопки разбора, см. ниже.
- **При закрытии:**
  - новые правила считаются просмотренными, синие точки гаснут;
  - строки «План применён…» и «Разбор откачен…» сбрасываются.

## Вкладка «Правила»

Правила — от новых к старым. Строка `.lesson` состоит из:
- синей точки нового правила (подсказка «Новое правило»);
- текста правила: Markdown, где `код` моноширинный, текст выделяется;
- строки происхождения;
- строки срабатываний.

Строка происхождения:
- «из ревью PR #N · авторы» / «из ответа в PR #N · авторы», а у склеенного разбором — с префиксом «склеено разбором · »;
- «из PR #N, исправлено вручную»;
- «добавлено вручную».

Текст с PR — ссылка-кнопка акцентным цветом, открывает PR в браузере. За ней « · 2 часа назад».

Срабатывания (`i-bolt`) — только когда учёт уже начат:
- «сработало: N · замечаний: N — исправлено N, отклонено N»;
- «не срабатывало» — третичным цветом.

Подсказка строки: «Сколько ревью учли это правило и чем кончились замечания, основанные на нём».

Справа две кнопки:
- карандаш «Изменить правило»;
- корзина «Удалить правило» — удаляет без подтверждения, как в SwiftUI.

Карандаш превращает строку в `.lesson-editor`:
- многострочное поле от 2 до 8 строк;
- «Отмена» и «Сохранить» (`.button--small`, «Сохранить» — `--prominent`);
- Enter сохраняет, Esc отменяет;
- «Сохранить» неактивна при пустом тексте.

## Вкладка «Разбор»

| Состояние | Что видно | Кнопки внизу |
|---|---|---|
| Плана нет | карточка «Разобрать память» с текстом и подсказкой о цене | «Разобрать память» (основная) |
| Идёт разбор | «Идёт разбор · 1 мин 12 с» синим, время каждую секунду, часы `.hourglass` переворачиваются | нет |
| План готов | карточка плана и группы «Склеить · N», «Переписать · N», «Удалить · N», под ними «Без изменений: N» | «Отказаться» слева, «Применить» (основная) справа |
| Изменений нет | то же, внизу «Менять нечего: все правила остаются как есть.» | «Убрать план», «Разобрать заново» |
| План устарел | в карточке оранжевое «Память изменилась после разбора — этот план уже не применить. Запустите разбор заново.» | «Отказаться», «Разобрать заново» (основная) |
| Применяется | — | «Отказаться» неактивна, справа индикатор и «Применяю…» |
| Применён | зелёная строка — последняя строка вывода, например «План применён: правил было 67, стало 59», под ней карточка «Разобрать память» | «Разобрать память» |
| Ошибка | карточка «Не получилось» оранжевым, текст ошибки моноширинный | как без плана |

Карточка плана:
- мета «Разбор 5 минут назад · $0.14 · правил 67 → 59»;
- итог модели Markdown'ом.

Подсказки кнопок:
- «Отказаться» — «Удалить план — память останется как есть»;
- «Применить» — «Склеить, переписать и удалить правила по плану. Применённый разбор можно откатить: pr-reviewer memory restore <slug>».

Строка действия `.plan-action`:
- причина — 12 semibold;
- удалённые правила — зачёркнуты, вторичным цветом;
- склеить и переписать — `.diff` с метками «было» / «станет» в колонке 52.

Подсветка слов — тот же алгоритм, что `WordDiff` (наибольшая общая подпоследовательность по словам):
- в «было» `<del>` красным 20 % — чего не осталось;
- в «станет» `<ins>` зелёным 20 % — что появилось;
- пробел между двумя изменёнными словами тоже подсвечен;
- `код` в обратных кавычках — моноширинный, подсветку не рвёт.

У склеенного правила «было» несколько строк. Новый текст сравнивается с ними всеми подряд.

## Вкладка «Что менялось»

Журнал от новых к старым, последние 100 записей. Запись — `.history-entry`.

**Шапка записи:**
- тег вида (`.tag` с `--tag-color`):

  | Вид | Тег | Цвет |
  |---|---|---|
  | `learn` | Выучено | `--fate-waiting` |
  | `add` | Добавлено вручную | `--fate-waiting` |
  | `review` | Разбор памяти | `--purple` |
  | `evict` | Вытеснено | `--fate-dismissed` |
  | `remove` | Удалено вручную | `--fate-dismissed` |
  | остальное | Исправлено вручную, Откат разбора | серый |

- точная дата «26 нояб., 11:42», с годом, если не текущий;
- ссылка «PR #N» (подсказка «Открыть PR в Bitbucket»).

**Строки записи:**
- причина записи — 12, вторичным;
- добавлено — `i-plus` зелёным;
- удалено — `i-minus` красным, текст зачёркнут, под ним причина 11;
- исправлено — `i-edit` оранжевым, причина и `.diff`;
- склеено — `i-merge` `--purple`, причина и `.diff`.

**Откат:**
- «Откатить» (`.button--small`, подсказка «Вернуть память к копии, сохранённой перед этим разбором») — только у последнего применённого разбора, если после него не было отката;
- пока идёт откат, вместо кнопки — `.spinner`;
- после отката над журналом зелёная строка — последняя строка вывода, например «Разбор откачен: правил было 59, стало 67»;
- ошибка — карточка «Откатить не получилось».

**Пустой журнал:** карточка «Журнал пуст: изменения памяти записываются с этой версии сервиса. Ручная правка файла в редакторе сюда не попадает.»

## Пустая и повреждённая память

- **Правил нет.** Вкладок нет, вместо них карточка «Изучить историю репозитория»:
  - сегменты «50 PR / 100 PR / 300 PR» по 70 px, по умолчанию 100;
  - кнопка «Изучить»;
  - во время изучения — индикатор и «Изучаю…», сегменты неактивны;
  - результат — строкой под ними;
  - подсказка о длительности третичным цветом.
- **Файл повреждён.**
  - Карточка: «Файл памяти повреждён» красным с `i-warning-fill`, текст ошибки моноширинный, пояснение, кнопка «Открыть в VS Code».
  - Поле своего правила и «Добавить» неактивны.

## Windows

- Рамка поповера из первой поставки, лист тот же.
- Проверить:
  - путь `\\wsl.localhost\…` для кнопки VS Code;
  - что заголовок и подпись листа в Segoe UI не обрезаются.

## Готово, когда

- Лист на Mac в светлой и тёмной теме совпадает с макетом. На Windows — то же содержимое. Проверка — скриншот рядом со страницей макета.
- Все состояния из таблиц работают на реальном сервисе: правка, удаление, добавление, разбор, применение, отказ, откат, изучение истории.
- Подсветка «было / станет» совпадает с SwiftUI на тех же правилах.
- Баннеры памяти открывают лист, заглушка памяти убрана.
