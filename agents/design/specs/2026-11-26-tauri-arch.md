# Спецификация: лист «Архитектурное ревью» в приложении Tauri (B-30, экран 3 из 8)

Дата: 26.11.2026, дизайнер. Одобрено пользователем 26.11.2026 («Одобряю»).
Макет: `agents/design/mockups/2026-11-26-tauri-arch.html`.
Источник поведения: `menubar/ArchViews.swift` (`ArchReportSheet`, `ArchText`), подтверждение запуска — `menubar/OverviewView.swift:50–63`.

## Главное

Лист отчёта переносится без изменений:
- шапка «Архитектурное ревью #N» с названием PR;
- строка статуса и баннер «Отчёт устарел»;
- отчёт: Итог, Цель · ясность, Как решено, Альтернативы, Можно проще, Серьёзные риски, Вопросы автору, Подробности;
- кнопки «Открыть PR», «Скопировать markdown», сохранить картинкой и кнопка запуска или остановки.

Тексты — слово в слово из SwiftUI. Действия — те же команды через API сервиса: запуск, остановка, markdown отчёта.

Разметка — шаблоны `tpl-sheet-*` и `tpl-arch-*` макета. Лист — общий компонент `.sheet` из листа памяти (B-32) с модификаторами:
- `.sheet--wide` — ширина 660;
- `.sheet--tall` — вся высота поповера, отчёт прокручивается внутри.

Классы отчёта: `.report-status`, `.report-paragraph`, `.alternative`, `.bullet`, `.place*`, `.detail-row`, `.output`, `.row-divider--marker` и `--tag`, `.button--destructive`. Баннер «Отчёт устарел» — обычный `.banner--warning`; поля внутри листа у баннера убраны правилом `.sheet .banner`.

Новые иконки:
- вердикты `i-verdict-keep`, `i-verdict-discuss`, `i-verdict-rework`;
- `i-scissors`, `i-question`;
- `i-plus-circle-fill`, `i-minus-circle-fill`.

## Что меняется по сравнению с SwiftUI

1. **Лист поверх поповера** на «Обзоре», подложка и закрытие — как у листа памяти. Заглушка «Архитектурное ревью» из первой поставки убирается.
2. **Высота.** В SwiftUI лист был 660 × (400 + шапка + кнопки) и в поповер 600 не помещался. Здесь у отчёта нет своей высоты 400: он занимает место между статусом и кнопками.
3. **Подтверждение запуска** — системный диалог Tauri. Заголовок «Архитектурное ревью #N?», текст из SwiftUI, кнопки «Отмена» и «Запустить» (основная). Сейчас это сделано в B-30.

## Строка статуса

| Состояние | Значок | Текст |
|---|---|---|
| В очереди | `i-clock`, вторичный | «В очереди», при прошлом отчёте — «В очереди. Ниже — прошлый отчёт», вторичным |
| Идёт | `i-hourglass` `.hourglass`, `--blue` | «Идёт ревью · 4 мин 12 с», при прошлом отчёте + «. Ниже — прошлый отчёт». Время каждую секунду. Под ним активность модели моноширинным 11, одна строка, многоточие посередине |
| Готово | значок вердикта цветом вердикта | название вердикта основным цветом |
| Ошибка | `i-warning-fill`, `--orange` | последняя строка ошибки оранжевым, выделяется |

Вердикты (`ArchText.verdict`):
- `keep` — «Оставить как есть», `--green`;
- `discuss` — «Стоит обсудить», `--yellow`;
- `rework` — «Лучше переделать», `--orange`.

## Баннер «Отчёт устарел»

Показывается, если отчёт снят не на текущем коммите PR и ревью не идёт:
- иконка `i-history`;
- заголовок «Отчёт устарел»;
- текст «Он снят на коммите <head отчёта>, а в PR уже <head PR>. Решение могло измениться — перезапустите ревью.».

Голову PR сверять со свежим снимком, пока лист открыт.

## Отчёт

Карточки — `.section` с заголовком капслоком. Текст — Markdown без заголовков: `код` моноширинный, переносы строк сохраняются, всё выделяется.

- **Итог, Цель, Как решено** — `.report-paragraph`. В заголовке цели — ясность: «описана автором», «восстановлена по коду», «непонятна».
- **Альтернативы · N** — `.alternative`:
  - справа от названия теги: «стоит рассмотреть» (зелёный, только если `better`) и цена переделки серым — «переделка — часы / день-два / больше двух дней»;
  - под ними идея;
  - плюсы — `i-plus-circle-fill` зелёным, минусы — `i-minus-circle-fill` оранжевым.
- **Можно проще · N** — `.place`: ножницы акцентным, заголовок, путь моноширинным в одну строку с многоточием посередине, пояснение. Разделитель с отступом 34.
- **Серьёзные риски · N** — `.place`: тег уровня — P0 красный, остальное оранжевый, по умолчанию «P1». Разделитель с отступом 46.
- **Вопросы автору · N** — `.place` со значком `i-question`.
- **Подробности** — `.detail-row`, подпись в колонке 130:
  - Модель — «Claude · модель»;
  - Коммит;
  - Снят — «26 нояб. 2026 г., 10:14»;
  - Цена и время — «$1.84 · 12 мин 40 с».

  Пустые строки не показываются.
- **Вывод** — при ошибке с многострочным текстом, `.output` моноширинным первой карточкой.

Многоточие посередине CSS не умеет — в классах стоит многоточие в конце. Путь и активность сокращает само приложение: начало и конец видны, середина заменена на «…», полный текст — в подсказке.

Пустые группы не показываются. Отчёта ещё не было — вместо отчёта текст «Архитектурного ревью этого PR ещё не было».

## Кнопки внизу

Слева:
- «Открыть PR» — открывает PR в браузере;
- «Скопировать markdown» — после копирования на 2 с становится «Скопировано»; без отчёта неактивна;
- камера `.square-button`, подсказка «Сохранить отчёт картинкой в «Загрузки»». Без отчёта неактивна, прозрачность 0,4.

Камера сохраняет шапку и весь отчёт без прокрутки, строки статуса, баннеров и кнопок. Ширина 660, файл `pr-reviewer-arch-<repo>-<id>…png` кладётся в «Загрузки» и открывается, как в B-25.

Справа одна кнопка:

| Состояние | Кнопка |
|---|---|
| В очереди или идёт | «Прервать», `.button--destructive` |
| Отчёт устарел | «Перезапустить», `--prominent`, Enter |
| Иначе | «Запустить снова» или «Запустить», если ревью не было |

Запуск закрывает лист и открывает подтверждение.

## Windows

Рамка поповера из первой поставки, лист тот же. Проверить: пути в «Можно проще» и «Рисках» обрезаются многоточием посередине, а не переносятся.

## Готово, когда

- Лист на Mac в светлой и тёмной теме совпадает с макетом, на Windows — то же содержимое. Проверка — скриншот рядом со страницей макета.
- Все состояния из таблиц работают на реальном сервисе: очередь, ход с активностью, готово, устарел, ошибка, прервать, перезапустить, копирование markdown, картинка.
- Колонна в строке PR открывает лист вместо заглушки.
