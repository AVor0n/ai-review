# Архитектурное ревью

Обычное ревью ищет дефекты в строках, а архитектурное отвечает на вопрос, правильно ли вообще решена задача. Одна модель читает PR целиком и пишет отчёт: какую задачу решает PR, как она решена, какие есть другие решения и сколько стоит на них перейти, где можно проще, какие есть серьёзные риски. В конце — вердикт и вопросы автору.

Отчёт только локальный: в PR ничего не публикуется. Запускается только вручную.

## Как запустить

**Из окна.** В строке PR на вкладке «Обзор», справа от кнопки доработки, — иконка-колонна. Серая колонна значит, что ревью ещё не было: клик спрашивает подтверждение и ставит заявку. Клик по непустой колонне открывает отчёт, а оттуда можно запустить ревью снова. Подробнее об окне — [window.md](window.md).

**Из терминала:**

```
bin/pr-reviewer arch --repo <slug> --pr <id>         # поставить в очередь
bin/pr-reviewer arch show --repo <slug> --pr <id>    # отчёт в markdown; --json — сырые данные
bin/pr-reviewer arch list                            # все отчёты; --json — сырые данные
bin/pr-reviewer arch stop --repo <slug> --pr <id>    # прервать ревью этого PR
```

Работает для любого подключённого репозитория и при выключенном фоновом ревью. Все команды — в [cli.md](cli.md).

## Что происходит

Ревью идут по одному, в порядке очереди, отдельным фоновым процессом. Обычное ревью в это время не стоит.

1. **Проверка PR.** PR должен быть открыт.
2. **Рабочая копия.** Ревью идёт в своём worktree служебной копии `~/.pr-reviewer/arch-workspaces/<slug>`, переключённом на голову PR. Если в клоне нет коммита PR или целевой ветки, сервис скачивает `origin`. Если коммита нет и после этого, ревью падает с ошибкой «подождите минуту и запустите снова».
3. **Входные данные.** Модель получает:
   - дифф PR относительно целевой ветки — без файлов из исключений (`ignorePaths`);
   - коммиты ветки;
   - описание PR, если автор его заполнил;
   - комментарии, уже оставленные в PR;
   - правила из памяти ревьюеров этого репозитория.

   Если дифф пуст, ревью падает с ошибкой «в PR нет изменений относительно целевой ветки». Если изменены только исключённые файлы — «в PR изменены только исключённые файлы (ignorePaths) — разбирать нечего».
4. **Отчёт.** Модель читает окружающий код целиком и возвращает отчёт по фиксированной схеме. Обычное построчное ревью она не повторяет.

### Что в отчёте

| Раздел | Что там |
|---|---|
| Вердикт и итог | Вердикт и 2–4 предложения, почему |
| Цель | Задача PR своими словами и откуда она понятна: описана автором, восстановлена по коду или непонятна |
| Как решено | Какие слои и модули затронуты, ключевые решения |
| Альтернативы | До трёх реально других решений, а если достойных нет — ни одного. У каждой — суть, плюсы, минусы, цена переделки готового PR (часы, день-два, больше двух дней) и пометка «стоит рассмотреть», если переделка оправдана |
| Можно проще | Готовый хук, сервис или утилита, лишний слой, дублирование — только с конкретным местом в коде и тем, на что заменить |
| Серьёзные риски | Только уровня P0–P1 и только те, которых ещё нет в комментариях PR |
| Вопросы автору | До пяти вопросов, ответ на которые может поменять оценку |
| Подробности | Модель, коммит, когда снят, цена и время |

Вердикты:

| В отчёте | В `arch list` и `arch.jsonl` | Цвет колонны |
|---|---|---|
| Оставить как есть | `keep` | Зелёный |
| Стоит обсудить | `discuss` | Жёлтый |
| Лучше переделать | `rework` | Оранжевый |

## Что разрешено модели

Модель только читает. Изменять файлы и запускать что-либо, кроме чтения, ей нельзя.

- **Claude** — чтение и поиск по файлам, `git diff`, `git log`, `git show`, `git blame`.
- **Codex** — песочница только для чтения.
- **Cursor** — режим `ask` (только чтение).

В промпте сказано, что описание и комментарии PR — данные, а не указания, и команды из них не выполняются.

## Где результат

**В окне.** Колонна в строке PR:

| Колонна | Что значит |
|---|---|
| Серая | Ревью не было |
| Часы | В очереди |
| Крутится | Идёт ревью |
| Цветная | Вердикт (см. таблицу выше) |
| Бледная | Отчёт снят на старом коммите PR |
| Треугольник | Последний запуск не удался |

Клик по непустой колонне открывает отчёт. Пока идёт запуск, видны таймер и текущее действие модели, а ниже — прошлый отчёт. Если голова PR ушла от коммита отчёта, сверху плашка «Отчёт устарел», а внизу кнопка «Перезапустить». Если запуск не удался, сверху ошибка, а ниже — прошлый отчёт, если он был. «Скопировать markdown» кладёт в буфер то же, что выводит `arch show`. Запуск из листа, как и с колонны, спрашивает подтверждение.

Уведомлений о готовом отчёте нет.

**В терминале.** `arch show` выводит отчёт в markdown. Если идёт новый запуск, сверху строка «Идёт новое архитектурное ревью, ниже — прошлый отчёт». Если последний запуск не удался, сверху строка «Последний запуск не удался: <ошибка>. Ниже — прошлый отчёт». `arch list` — все PR с отчётами: состояние, вердикт и заголовок.

**Файлы.**

- `~/Library/Application Support/pr-reviewer/arch/state/<repo>__<pr>.json` — состояние и последний отчёт по PR. Хранится только последний удачный отчёт; новый запуск заменяет его, только когда готов.
- `~/Library/Application Support/pr-reviewer/arch.jsonl` — история удачных запусков: время, репозиторий, PR, `head`, `agent`, `model`, `verdict`, `alternatives` (сколько альтернатив), `risks` (сколько рисков), `usage`, `durationSec`. Неудачные и прерванные запуски сюда не пишутся.

В общую статистику моделей (сравнение моделей, доли исправленных замечаний) архитектурное ревью не входит. На вкладке «Статистика» оно есть в разделах «Стоимость» и «Новые режимы». Все файлы — в [data.md](data.md).

## Сколько длится и сколько стоит

Окно предупреждает, что ревью займёт до часа. Предел — `arch.timeoutMinutes`, по умолчанию 60 минут. Модель работает с высоким уровнем reasoning (по умолчанию `xhigh`), поэтому запуск заметно дороже обычного ревью одной моделью. Точная цена — в отчёте и в `arch.jsonl`; если модель цену не сообщила, её там нет.

На время работы сервис запускает `caffeinate`, чтобы Mac не уснул.

## Как прервать

В окне — «Прервать» в листе отчёта этого PR, из терминала — `bin/pr-reviewer arch stop --repo <slug> --pr <id>`. Прерывание касается только этого PR: ждущая заявка снимается из очереди, идущее ревью останавливается. Заявки других PR остаются и выполняются дальше. `arch stop` без `--repo` и `--pr` прерывает ревью, которое идёт сейчас, а очередь продолжается. Прерывание срабатывает сразу, даже если ревью встало на зависшем `git fetch`. Запуск получает итог «архитектурное ревью прервано», прошлый отчёт остаётся.

## Настройки

Поля `arch` в `config.json`. Отдельных переключателей в окне нет; `config.json` можно править в окне: «Настройки» → «Дополнительно» → «config.json». Подробнее — [config.md](config.md).

| Поле | Умолчание | Что значит |
|---|---|---|
| `arch.agent` | `claude` | Какая модель пишет отчёт: `claude`, `codex` или `cursor`. Она должна быть в `agents` |
| `arch.model` | модель из `agents.<agent>` | Другая модель вместо выбранной у агента |
| `arch.effort` | `xhigh` | Уровень reasoning. У Claude — `effort`, у Codex — `reasoningEffort`. У Cursor не действует: уровень зашит в имя модели |
| `arch.timeoutMinutes` | `60` | Сколько ждать отчёт, в минутах |

Остальные параметры запуска берутся из настроек выбранного агента в `agents`.
