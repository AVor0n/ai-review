# Типичные проблемы

Сначала — где смотреть:

- **Журнал** — вкладка «Журнал» с фильтром «Ошибки» или `~/Library/Logs/pr-reviewer/worker.log`. Ошибки помечены `ERROR`, в том числе ошибки команд, которые окно запускало без терминала.
- **Состояние** — `bin/pr-reviewer status`: пауза, что идёт, последняя ошибка, последние ревью.
- **Если воркер не стартует вовсе** — `launchctl print gui/$(id -u)/com.avoronin.pr-reviewer` и `~/Library/Logs/pr-reviewer/launchd.err.log`.

## Bitbucket и токены

**«Bitbucket не принял токен (401)…»** — неверный `bitbucket.email` или токен в Keychain. Частая причина — токен сохранили через интерактивный `security … -w` без значения: он молча обрезает ввод до 128 символов. Пересохраните токен командой из [install.md](install.md). Если токен просто истёк, в обзоре висит красный баннер «Токен».

**«Bitbucket запретил запрос (403)…»** — у токена нет нужных scope: нужны `read:repository`, `read:pullrequest`, `write:pullrequest` для Bitbucket.

**«Нет токена Bitbucket в Keychain (service …, account …)»** — записи нет или у неё другое имя аккаунта: аккаунт должен совпадать с `bitbucket.email`.

**«Нет связи с Bitbucket (…)»** — сеть пропала (сон Mac, VPN). Чтение повторяется трижды; следующий проход попробует снова. Публикация не повторяется, чтобы не задвоить комментарий.

**Ошибка `claude: …` с упоминанием авторизации или токена** — истёк токен `claude setup-token`. Выпустите новый и сохраните в Keychain (`pr-reviewer-claude`).

**«cursor: нет API-ключа в Keychain (pr-reviewer-cursor)»** — ключ Cursor не сохранён. Сохраните его (см. [install.md](install.md)) или выключите Cursor из фонового ревью: `bin/pr-reviewer agent set cursor --auto off`.

## Ревью не идёт

**Сервис ничего не делает.** Проверьте по порядку:

1. Фоновое ревью выключено — `bin/pr-reviewer status` (в нём «пауза») или переключатель «Фоновое ревью». Первая установка оставляет фоновое ревью выключенным.
2. Интервал — проход начинается раз в `intervalMinutes`; кнопка ▶ в обзоре запускает его сразу.
3. Агент launchd загружен — `launchctl print …` выше. Если нет — `./install.sh`.

**Модель не ревьюит конкретный PR.** Сначала наведите курсор на серый «0» в строке PR и на значок модели: подсказки называют причину, а бейдж на значке и капсулы в шапке обзора показывают исчерпанный лимит и модели только для ручного запуска. Фоновое ревью пропускает:

- черновики;
- PR, исходная ветка которых не подходит под `branchPattern` (тег «Untracked» в обзоре; проверить — «Настройки» → «Дополнительно» → «Ветки для ревью»);
- репозитории с выключенным фоновым ревью;
- модели с `auto: false`;
- головы, у которых изменения те же, что на прошлом ревью (rebase), пустой дифф или в диффе только исключённые файлы — об этом есть запись в журнале.

Любой из этих PR можно отревьюить вручную кликом по иконке модели. Подробно — [review.md](review.md).

**В журнале «коммит … ещё не пришёл с fetch, пропускаю до следующего запуска»** — Bitbucket уже знает о новом коммите, а в служебной копии его ещё нет. Следующий проход скачает его.

**«предыдущий запуск ещё идёт»** — другой проход держит лок. Если он завис — см. ниже.

## Проход завис

Оранжевый треугольник в строке меню и баннер «Проход ревью не продвигается» — пульс прохода не обновлялся 15 минут. Обычно это синхронный git, который ждёт мёртвую сеть. Нажмите «Прервать» в баннере или `bin/pr-reviewer stop` (`pause` тоже прерывает): проход останавливается сразу, вместе с зависшим `git fetch` или `clone`, а следующий начнётся по расписанию. Если повторяется, посмотрите в журнале, на каком шаге он встаёт: время последней записи показано в баннере.

**Ошибки git про блокировки (`cannot lock ref`, `….lock`)** — обычно остаются от прерванного git, например после «Прервать» посреди `fetch`. Сервис сам удаляет блокировки старше 10 минут и обходит конфликт веток, различающихся только регистром, поэтому чаще всего достаточно дождаться следующего прохода.

**«превышен таймаут N мин»** — модель не уложилась в `timeoutMinutes` своего агента (или `fix`, `arch`, `qa`). Для больших PR таймаут можно поднять (см. [config.md](config.md)).

## Замечания

**Замечание стоит не на той строке.** Модель назвала строку, которой нет в диффе, и сервис привязал замечание к ближайшей строке диффа этого файла. Если файла в диффе нет вовсе, замечание не публикуется (в статистике — `dropped`).

**Модель повторяет замечание, которое команда уже отклонила.** Ответьте в треде, почему так задумано: на следующем проходе память ревьюеров выделит из ответа правило. Или добавьте правило сами — лист 🧠 в настройках или `memory add` (см. [memory.md](memory.md)).

**«<модель>: ответ не соответствует схеме»** — модель вернула JSON не того вида. Ревью этой модели в этом проходе пропущено; следующий проход попробует снова. Cursor получает одну попытку исправить ответ сразу.

## Окно

**Правка в `menubar/` не видна.** Установленное приложение собирается `install.sh` и само не обновляется: запустите `./install.sh --app-only` — пересоберёт и перезапустит только приложение, сервис не тронет. Какая сборка сейчас установлена, видно внизу «Настроек» (коммит и дата); сравните коммит с `git log`.

**«Сборка приложения не удалась, установленное приложение не тронуто».** `swiftc` не собрал `menubar/`: ошибки компиляции — выше в выводе `install.sh`. Старое приложение продолжает работать, его можно пересобрать после исправления.

**После обновления `node`, `claude`, `codex` или `cursor-agent` сервис их не находит.** Пути к ним зашиты в `bin/pr-reviewer` при установке — запустите `./install.sh`.

**«Лимит недоступен» или остаток не меняется.** У Codex он берётся из входа `codex login`, у Cursor — по API-ключу из Keychain (`pr-reviewer-cursor`): без ключа лимита Cursor нет. Лимит Claude появляется после его первого запуска. Если опрос не удался, у строки оранжевый треугольник и «не обновляется», причина — в подсказке: «нет доступа» — API-ключ или вход недействителен, «нет API-ключа в Keychain» — ключ не сохранён (см. [install.md](install.md)), «нет входа Codex» — выполните `codex login`. Все состояния строки — в [stats.md](stats.md). `bin/pr-reviewer limits` обновит остатки и напечатает ошибку.

**Оранжевый баннер «Не удалось прочитать данные сервиса».** Окно два раза подряд не смогло прочитать файл из `~/Library/Application Support/pr-reviewer/`. «Ошибка формата» — файл испортили вручную или его дописывают прямо сейчас: если баннер не уходит, откройте файл кнопкой «Показать в Finder» и почините JSON или удалите файл, если [data.md](data.md) говорит, что он пересоздаётся. «Нет доступа» — проверьте права на файл. Пока файл не читается, окно показывает последние прочитанные данные.

**Красный баннер «Память сломана».** Файл `memory/<slug>.json` стал невалидным после ручной правки (сломан JSON, нет массива `lessons`, у правила нет `id`, `text` или `at`). Пока файл не починят, ревью идёт без правил этого репозитория, а новые правила не сохраняются. Кнопка в баннере открывает файл в VS Code.

**«Тестирование в браузере пока только для <репозиторий>»** — тестирование работает только для `qa.frontend`.
