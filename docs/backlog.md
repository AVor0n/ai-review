# Бэклог проблем вне скоупа PR

Бэклог — список проблем, которые модели нашли по ходу ревью, но которые не относятся к самому PR: дефект был в коде ещё до него. Команда отклоняет такие замечания в PR, даже когда они верны по сути, поэтому сервис не публикует их, а складывает в бэклог. Раз в неделю бэклог разбирают: по важному заводят задачу, остальное отклоняют.

Бэклог общий для всех моделей и репозиториев. Модели видят его при ревью кода и не находят известные проблемы заново.

## Как это работает

### Откуда берутся записи

Запись появляется в четырёх случаях. В окне у каждого источника своя подпись в блоке «Где нашли».

| Источник | Когда | Подпись в окне |
|---|---|---|
| Находка при ревью | Модель отметила замечание как бывшее до PR (`origin: "preexisting"`). В PR оно не публикуется | «нашла при ревью» |
| Ответ в треде | Проверяющая модель ответила на чужое замечание «Не согласен» с причиной `preexisting`. В её ответе есть строка «📋 Проблема была до PR — записана в бэклог для отдельной задачи.», так что тред можно закрывать. Если пояснения у модели нет, ответ в PR не публикуется, а запись всё равно появляется | «признала старой проблемой замечание в треде» |
| Отложено человеком | Человек в треде модели не спорит с замечанием, а откладывает его («сделаем позже», «отдельной задачей»). Модель закрывает свой тред с пометкой «✓ Отложено в бэклог: <почему>», а замечание уходит в бэклог. Запись делается до закрытия треда, поэтому сбой Resolve её не теряет | «автор PR отложил замечание» |
| Сбор из истории PR | Модель разобрала незакрытые треды влитых PR (см. ниже) | «из незакрытого треда влитого PR» |

Находка с `origin: "preexisting"` уходит в бэклог раньше фильтра редких P3. Поэтому редкий старый P3 считается в `backlogged`, а не в `filtered` (поля `stats.jsonl`, см. [stats.md](stats.md)). Сколько новых записей дал запуск ревью — `backlogged`; повтор уже известной проблемы туда не входит.

Подробнее про оси `origin` и `likelihood`, про закрытие своих тредов моделями — в [review.md](review.md).

### Повторы склеиваются

Одна старая проблема находится в каждом PR, который трогает файл, и у каждой модели. Новая находка считается той же записью, если совпадает репозиторий и файл, а также:

- заголовок, без учёта регистра и пунктуации, или
- строка — в пределах двух строк.

У записей без файла совпадением считается тот же заголовок.

Тогда к записи добавляется ещё один источник — PR и модель. Пара «тот же PR и та же модель» второй раз не добавляется. Уровень записи поднимается до самого высокого из найденных.

Совпадение ищется и среди разобранных записей. Повторная находка добавляет источник, но не открывает запись заново: заведённая задача и отклонение остаются в силе.

### Что модель видит при ревью

При ревью кода в `.pr-review/backlog.md` кладётся список известных проблем репозитория — и ждущих разбора, и разобранных. В списке не больше 100 записей: сначала по уровню, затем по числу источников. Модель получает указание не возвращать эти проблемы повторно. Запуски, где модель только отвечает в тредах, списка не получают.

### Еженедельный разбор

Итог по каждой записи ставит человек:

- **задача заведена** — можно указать номер задачи;
- **отклонено** — можно указать причину;
- **вернуть** — снова в «Ждут разбора».

Отклонённая запись остаётся в бэклоге. Модели и дальше знают о проблеме и не находят её заново.

### Разбор по коду (triage)

Записи сделаны по старым версиям кода: с тех пор проблему могли исправить или код удалить. Разбор по коду помогает это увидеть.

Для каждого репозитория, где есть записи, ждущие разбора, модель читает код основной ветки. Основная ветка берётся из Bitbucket (`mainbranch`); если Bitbucket её не вернул — `master`. Работа идёт в отдельной рабочей копии `~/.pr-reviewer/backlog-workspaces/<slug>` (worktree служебного клона), чтобы не мешать ревью, которое переключает сам клон на ветки PR. Репозитории без ждущих записей пропускаются.

Модель смотрит записи пачками по 10 и ставит каждой вердикт с причиной:

| Вердикт | Значит | Можно закрыть |
|---|---|---|
| `actual` — «актуально» | Проблема на месте. Если код сдвинулся, у записи обновляются файл и строка | нет |
| `fixed` — «решено» | Код изменён, сценарий больше не ведёт к ошибке | да |
| `gone` — «удалено» | Кода, о котором запись, больше нет | да |
| `invalid` — «не баг» | Анализ в записи ошибочен | да |
| `unclear` — «неясно» | По коду не понять, например зависит от данных или сервера | нет |

Модели передаются и правила из [памяти ревьюеров](memory.md) этого репозитория.

Сам разбор ничего не закрывает — закрывает человек. Неактуальные записи («решено», «удалено», «не баг») можно отклонить по одной или все сразу. Причина отклонения тогда — «Неактуально (<вердикт>): <причина из разбора>».

Запись, уже проверенная на той же голове основной ветки, повторно не проверяется. Исключение — запись изменилась после проверки: например, к ней добавился новый источник или её вернули в ожидание.

### Сбор из истории PR (learn)

Бэклог появился позже, чем команда начала откладывать замечания. Сбор из истории находит такие проблемы в старых PR.

Сервис берёт последние N PR репозитория любого состояния, по дате обновления (по умолчанию 100). Из них остаются влитые PR с комментариями. В них модель смотрит треды, которые так и не закрыли через Resolve: замечания моделей и людей, оставленные как есть. Треды отдаются модели пачками по 25.

Модель берёт только реальные дефекты, которые остались в коде: команда отложила их, не ответила или согласилась, но не исправила. Исправленное, оспоренное по существу, вопросы и вкусовщина не берутся. Список уже известных проблем репозитория модель получает, чтобы не повторять их.

Разобранные треды запоминаются в `backlog-scan.json` — по id последнего комментария. Повторный запуск смотрит только новые треды и треды с новыми комментариями; если таких нет, он заканчивается без модели. Прогресс сохраняется после каждой пачки, поэтому прерванный сбор продолжит с того же места.

### Задачи идут в фоне

Разбор по коду и сбор из истории — долгие задачи. Они идут отдельным процессом, по одной за раз: вторая не запустится, пока идёт первая. Ход и итог пишутся в `backlog-job.json`, оттуда их показывает окно. Прерывание останавливает и модель.

Модель для обеих задач — `memory.agent` в `config.json` (по умолчанию Claude). Таймаут одного вызова — `timeoutMinutes` этой модели, без поля — 30 минут.

## Как пользоваться

### В окне

Вкладка «Бэклог». Записи сгруппированы по репозиториям в порядке обзора; отключённые репозитории, у которых остались записи, — в конце. Внутри группы — по уровню, затем по числу источников, как в `backlog export`.

Сверху — переключатель «Ждут разбора» / «Все». В режиме «Все» разобранные записи приглушены и проявляются под курсором.

У записи видно:

- уровень и заголовок;
- «найдено в» — ссылки на PR, кто нашёл (модели или человек из треда);
- метку «редкий случай» или «гонка или сбой», если модель так оценила сценарий;
- вердикт разбора по коду, кроме «актуально».

Клик по записи раскрывает подробности: файл и строку (ссылка на файл в Bitbucket на коммите, где нашли проблему), сценарий, исправление, причину отклонения, итог разбора по коду с коммитом основной ветки, список источников и id записи.

Кнопки у записи:

- **«Задача заведена»** — поле для номера задачи (необязательно). То же, что `backlog filed`.
- **«Отклонить»** — поле для причины (необязательно). То же, что `backlog drop`.
- **«Закрыть»** — вместо «Отклонить» у записи, которую разбор счёл неактуальной: отклоняет с причиной из разбора, без поля.
- **«Вернуть»** — у разобранной записи, снова в «Ждут разбора». То же, что `backlog reopen`.

**«Скопировать .md»** кладёт в буфер markdown для разбора — вывод `backlog export`, в режиме «Все» — с `--all`.

**«Разобрать»** — разбор по коду всех репозиториев. Кнопка видна, когда есть записи, ждущие разбора, и никакая задача бэклога не идёт. Перед запуском окно спрашивает подтверждение. Когда разбор нашёл неактуальные записи, сверху появляется плашка «Похоже, неактуальны: N» с кнопкой «Закрыть все» — это `backlog close-stale`.

**«Собрать из истории PR»** — кнопка в пустом списке, когда разбирать нечего. Под ней — дата последнего сбора и сколько он нашёл.

Пока задача идёт, сверху видна плашка: что делает модель и кнопка «Прервать». После окончания плашка показывает итог или ошибку; её можно закрыть крестиком. Если команда не выполнилась, появляется плашка «Не удалось выполнить команду» с текстом ошибки.

Окно запускает задачи с `--background` и ждёт их по файлу задачи. Подробнее про окно — [window.md](window.md).

### В терминале

```
bin/pr-reviewer backlog list [--repo <slug>] [--all] [--json]
bin/pr-reviewer backlog export [--repo <slug>] [--all] [--json]
bin/pr-reviewer backlog filed <id> [задача]
bin/pr-reviewer backlog drop <id> [причина]
bin/pr-reviewer backlog reopen <id>
bin/pr-reviewer backlog triage [--repo <slug>] [--dry-run] [--background]
bin/pr-reviewer backlog close-stale [--repo <slug>]
bin/pr-reviewer backlog learn [--repo <slug>] [--prs <N>] [--dry-run] [--background]
bin/pr-reviewer backlog stop
```

- `list` — коротко, по строке на запись; без `--all` — только ждущие разбора.
- `export` — markdown по репозиториям: самые важные и часто встречающиеся сверху, со сценарием, исправлением и ссылками на PR.
- `triage --dry-run` — сколько записей ждут разбора и сколько из них уже проверено по коду; модель не запускается.
- `learn --dry-run` — сколько влитых PR с комментариями и новых незакрытых тредов; модель не запускается.
- Без `--background` задача идёт в терминале, и ход видно в выводе. С `--background` команда сразу возвращается.
- `stop` прерывает идущую задачу.

Полный справочник команд — [cli.md](cli.md).

## Где хранится

| Файл | Что в нём |
|---|---|
| `~/Library/Application Support/pr-reviewer/backlog.json` | Все записи бэклога |
| `~/Library/Application Support/pr-reviewer/backlog-job.json` | Последняя задача бэклога: вид, состояние, текущее действие, итог или ошибка |
| `~/Library/Application Support/pr-reviewer/backlog-scan.json` | Что уже разобрано сбором из истории: по репозиториям — треды, дата и сколько найдено |
| `~/.pr-reviewer/backlog-workspaces/<slug>` | Рабочие копии основной ветки для разбора по коду |

Поля записи в `backlog.json`:

| Поле | Что это |
|---|---|
| `id` | Короткий id записи, 6 символов |
| `status` | `open` — ждёт разбора, `filed` — задача заведена, `dropped` — отклонено |
| `repo`, `path`, `line` | Репозиторий, файл и строка; файла и строки может не быть |
| `level` | P0–P3 |
| `likelihood` | `usual`, `rare`, `race` или `null` |
| `title`, `scenario`, `fix` | Заголовок, сценарий, вариант исправления |
| `sources` | Где нашли: `pr`, `url`, `agent` (`human` — человек), `author` (у сбора из истории), `commit`, `kind` (`finding`, `reply`, `deferred`, `history`), `at` |
| `triage` | Итог разбора по коду: `at`, `commit`, `branch`, `verdict`, `reason` |
| `ticket` | Номер задачи из «Задача заведена» |
| `note` | Причина отклонения |
| `createdAt`, `updatedAt` | Когда запись появилась и когда менялась |

Остальные файлы сервиса — в [data.md](data.md).

## Сколько стоит

Записи из ревью ничего не стоят отдельно: модель отмечает их в том же запуске ревью.

Разбор по коду и сбор из истории — отдельные запуски модели. Их цена пишется в `spend.jsonl` с видом `backlog-triage` и `backlog-learn` и видна в разделе «Стоимость» на вкладке «Статистика» как «Бэклог». Как считается цена — в [stats.md](stats.md).

По журналу сервиса:

- разбор по коду: 27 записей — $2.42, 14 записей — $1.28, то есть около $0.9 за 10 записей. Окно в подтверждении пишет «около $0.2 за 10 записей» — это заниженная оценка;
- сбор из истории: 128 тредов в трёх репозиториях — $0.65.

Цена растёт с размером репозитория: модель читает код сама.

## Настройки

| Что | Где |
|---|---|
| Модель для задач бэклога | `memory.agent` в `config.json`: `claude`, `codex` или `cursor`; по умолчанию `claude`. Та же модель ведёт память ревьюеров |
| Таймаут вызова модели | `timeoutMinutes` у этой модели в `agents` |
| Сколько PR смотрит сбор из истории | `--prs <N>` в терминале; окно всегда берёт 100 |

Отдельной настройки, чтобы выключить бэклог, нет. Подробно про поля — [config.md](config.md).

## Известные проблемы

- Подсказка кнопки «Собрать из истории PR» и справка `backlog learn` говорят о «последних 100 влитых PR». На деле берутся последние 100 PR любого состояния, а влитые выбираются уже из них — влитых может оказаться меньше.
- Оценка «около $0.2 за 10 записей» в подтверждении разбора по коду занижена примерно вчетверо (см. «Сколько стоит»).
