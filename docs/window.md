# Приложение в строке меню

Приложение — иконка в строке меню и окно под ней. Оно ничего не делает с PR само: читает файлы сервиса и вызывает команды CLI (см. [cli.md](cli.md)). Поэтому всё, что видно в окне, можно получить и из терминала.

## Иконка

Число рядом с иконкой — открытые PR, текущий коммит которых ещё не проверила хотя бы одна модель фонового ревью. Черновики, PR с веткой не по `branchPattern` и репозитории с выключенным фоновым ревью не считаются.

| Иконка | Что значит |
|---|---|
| Пузырь с галочкой | Ожидание: всё проверено, проход не идёт |
| Крутящийся значок модели (Claude, Codex или Cursor) | Эта модель сейчас ревьюит |
| Крутящийся значок Claude во время доработки | Идёт доработка по замечаниям |
| Пузырь с многоточием | Проход идёт, но модель сейчас не работает (запросы к Bitbucket, git) |
| Пауза | Фоновое ревью выключено |
| Красный пузырь с восклицательным знаком | Последний проход закончился ошибкой |
| Оранжевый треугольник | Проход завис: пульс не обновлялся 15 минут. Первые секунды мигает, дальше горит ровно |

В подсказке иконки — что идёт сейчас, сколько PR без ревью, сколько важных замечаний ждут правки и до какого времени выключены уведомления.

**Клик** открывает окно; повторный клик, клик в другом приложении или Esc его закрывают. **Правый клик** (или Ctrl-клик) — меню:

- серая строка — что сейчас: «Идёт ревью: <репозиторий> #<PR> · <модель> (<роль>)», «Идёт доработка · Claude», «Проход не продвигается N мин», «Фоновое ревью выключено», «Последний проход завершился с ошибкой» или «Следующий проход через N мин»;
- «Прервать ревью», пока идёт проход или ручной запуск (`stop`: очередь ручных запусков тоже очищается), или «Проверить сейчас», когда проход не идёт и фоновое ревью включено (`run-now`);
- «Выключить фоновое ревью» или «Включить фоновое ревью» (`pause` / `resume`; выключение прерывает идущий проход);
- уведомления и выход — ниже.

Уведомления в меню: «Выключить уведомления» на 1, 2, 4, 8, 12 или 24 часа либо «Пока не включу» (когда выключены — срок, «Включить уведомления» и «Выключить на другое время») и «Выйти из PR Reviewer» (⌘Q).

## Вкладки

«Обзор», «Бэклог», «Статистика», «Журнал», «Настройки». Отчёты доработки, архитектурного ревью и тестирования открываются листами из строки PR; токены, память и редактор конфига — листами из настроек.

## Обзор

### Строка состояния

Сверху — что идёт сейчас и когда следующий проход. Кнопки: ▶ — запустить проход сейчас (`run-now`), «Прервать» во время прохода (`stop`), обновить список PR (`sync`). При выключенном фоновом ревью — статус «Фоновое ревью выключено» (в подсказке: работают только запуски по иконкам) и кнопка «Включить». При открытии окна список PR обновляется сам, не чаще раза в минуту.

Справа, перед кнопками, — капсулы моделей в особом состоянии, сначала лимит, потом «только вручную»:

- **«Codex: лимит до 14:00»** (красная) — модель исчерпала лимит подписки; после сброса снова начнёт ревью сама. Время сброса — «до 14:00» сегодня, «до завтра 14:00» или дата. Лимит считается исчерпанным, только если израсходовано 100%, сброс ещё впереди и остаток обновлялся не больше часа назад; иначе капсулы нет (см. [stats.md](stats.md)).
- **«Cursor: только вручную»** (серая) — модель вне фонового ревью (`auto: false`). При выключенном фоновом ревью этих капсул нет: тогда вручную работают все модели.

Клик по капсуле открывает «Настройки».

### Баннеры

Над списком могут висеть баннеры, по важности:

- **Проход не продвигается** — пульс не обновлялся 15 минут. Кнопки «Прервать» (останавливает проход сразу, даже зависший git) и «Журнал».
- **Ошибка** последнего прохода или команды из окна — со ссылкой на журнал.
- **Токен** скоро истечёт (жёлтый, за 14 дней; закрывается до следующего дня) или истёк (красный, не закрывается).
- **Память сломана** — файл памяти репозитория невалиден после ручной правки; кнопка «Открыть в VS Code».
- **Память заполнена** на 80% и больше — переход к памяти.
- **Новые правила в памяти** — последнее правило и кнопка «Посмотреть»; закрывается крестиком.

### Список PR

PR сгруппированы по репозиториям, секции сворачиваются. Если у репозитория выключено фоновое ревью, а общее включено, в заголовке секции — оранжевая пауза и «фоновое ревью выключено». Черновики стоят внизу и приглушены (тег «Draft»), PR вне `branchPattern` — на своём месте с тегом «Untracked». У строки PR:

- **Иконки моделей** слева (Claude, Codex, Cursor): серая — ревью не было, бледная — ревью на старом коммите, цветная — ревью актуально, крутится — в очереди или идёт. Бейдж в углу: красные песочные часы — лимит исчерпан, серая пауза — модель только для ручного запуска (его нет при выключенном фоновом ревью — общем или репозитория). Подсказка называет причину, если ревью нет или оно пропущено: «ревью не было — модель только для ручного запуска», «лимит исчерпан до 14:00 — ревью будет после сброса», «повторное ревью не нужно — после rebase изменения те же», «ревью не понадобилось — в диффе только исключённые файлы» или «…в PR нет изменений относительно целевой ветки». Клик — ручной запуск этой модели: он выполняется даже при выключенном фоновом ревью и для черновиков (см. [review.md](review.md)). При красном бейдже кнопка тоже работает: данные о лимите могут устареть.
- **Треды** — «закрытые/всего» (только «всего», пока ни один не закрыт; зелёный — все закрыты), время обновления. Без комментариев — серый «0». Его подсказка называет причину, почему ревью ещё нет, — первую подходящую: фоновое ревью выключено, фоновое ревью репозитория выключено, черновик, ветка вне шаблона веток задач, все модели только для ручного запуска («фоновое ревью этот PR не возьмёт»), все фоновые модели упёрлись в лимит, идёт проход или «ждёт прохода, следующий через N мин». Если часть моделей уже проверила коммит, подробности — у значков моделей.
- **Залитая зелёная галочка** вместо счётчика — комментариев в PR нет, и все модели фонового ревью проверили текущий коммит (их иконки цветные). Модели, выключенные из фона, не учитываются; если в фоне нет ни одной модели, галочки нет. После нового коммита снова серый «0», пока его не проверят. То, что модели нашли, но отправили в бэклог или отфильтровали как редкий P3, галочке не мешает: в PR это не публикуется (см. [review.md](review.md)). Галочка ставится и когда ревью пропущено (см. [review.md](review.md)): если в диффе только исключённые файлы или он пуст, подсказка говорит «Ревью не понадобилось: …» вместо «Модели проверили последний коммит и замечаний не нашли».
- **Бейдж P0/P1** — красный или оранжевый: важные замечания, строки которых ещё не правили (с «+N», если их несколько). Клик открывает замечание.
- **Доработка** — волшебная палочка: «Исправить» по открытым тредам. Если тредов нет, а ветка отстала от целевой, — «Rebase» (оранжевый, если будут конфликты). После доработки галочка; жёлтая — если появились новые треды. См. [fix.md](fix.md).
- **Архитектурное ревью** — колонна: серая — не было, часы — в очереди, крутится — идёт, цветная — вердикт (зелёная — оставить, жёлтая — обсудить, оранжевая — переделать), бледная — отчёт на старом коммите, треугольник — запуск не удался. См. [arch.md](arch.md).
- **Тестирование** — пробирка, только у PR репозитория из `qa.frontend`: серая — не было, синяя — план готов, часы — в очереди, крутится — идёт; после прогона красная (найдена ошибка), оранжевая (есть неподтверждённые кейсы) или зелёная (всё прошло); треугольник — не удалось. См. [qa.md](qa.md).

## Бэклог

Проблемы вне скоупа PR для еженедельного разбора: фильтр «Ждут разбора» или «Все», «Задача заведена», «Отклонить», «Вернуть», разбор моделью «Разобрать» и сбор «Собрать из истории PR». Подробно — [backlog.md](backlog.md).

## Статистика

Шум, качество кода, время до исправления, сравнение моделей, стоимость, доработка («Автофикс») и новые режимы — с фильтрами по репозиторию, автору, модели и типу ревью, за 7, 30 или 90 дней. Подробно — [stats.md](stats.md).

## Журнал

Последние записи `worker.log` (не больше 300), ошибки выделены, фильтр «Ошибки». Длинные записи раскрываются по клику. «Открыть файл» открывает журнал целиком.

## Настройки

- **Фоновое ревью** — общий переключатель (то же, что `pause`/`resume`) и интервал между проходами (1–240 минут).
- **Репозитории** — подключить («Добавить репозиторий»: доступ проверяется через Bitbucket API, затем скачивается служебная копия), выключить его фоновое ревью. В меню «…» у репозитория — «Открыть в Bitbucket», «Показать служебную копию в Finder», «Отключить…» (с удалением клона); кнопка «Скачать», если клона нет. Значок 🧠 — лист памяти (см. [memory.md](memory.md)): синяя точка — новые правила, красная — файл памяти сломан.
- **Модели** — для Claude и Codex модель и уровень reasoning (список моделей Codex — из `~/.codex/models_cache.json`), для Cursor модель (уровень — в её названии; список обновляется командой `agent models cursor` не чаще раза в сутки). Рядом — остаток лимита подписки и участие в фоновом ревью: выключенная модель в фоне не ревьюит, не отвечает и не закрывает свои треды, но запускается по клику на иконку.
- **Уведомления** — см. ниже.
- **Тема** — системная, светлая или тёмная.
- **Сборка** — внизу настроек: из какого коммита и когда собрано приложение; тег «правки не закоммичены», если при сборке были незакоммиченные правки окна (см. [install.md](install.md)).
- **Дополнительно:**
  - «Ветки для ревью» — `branchPattern` и список открытых PR с отметкой, подходят ли они;
  - «Исключения из диффа» — `ignorePaths`;
  - «Токены» — сроки токенов (см. ниже);
  - «config.json» — редактор конфига с подсветкой, описанием поля под курсором и проверкой по схеме перед сохранением; ⌘S сохраняет, «Перечитать» — если файл изменили снаружи. «Открыть в VS Code» (без VS Code — Cursor или программа по умолчанию). Поля — в [config.md](config.md).

### Токены

Срок в самом токене прочитать нельзя, поэтому он считается от даты сохранения записи в Keychain плюс срок, выбранный при выпуске (`tokenLifetimeDays`, или `bin/pr-reviewer token <bitbucket|claude|cursor> <дней|never>`). У Atlassian и `claude setup-token` по умолчанию год, у Cursor срок нужно указать. В листе — ссылка или команда для выпуска нового токена и команда сохранения в Keychain; после сохранения дата обновится сама.

## Уведомления

Все уведомления шлёт приложение: раз в 5 секунд оно сравнивает файлы сервиса с тем, о чём уже сообщило. Клик по уведомлению (или кнопка «Открыть PR») открывает PR или тред. При первом запуске macOS спросит разрешение; если уведомления запрещены, в настройках будет кнопка «Открыть системные настройки».

| Что | По умолчанию |
|---|---|
| Замечания моделей — с порогом уровня: P0–P1, P0–P2 или все | вкл., P0–P1 |
| Комментарии людей — новые треды и ответы, кроме ваших (по аккаунту владельца токена Bitbucket) | вкл. |
| Завершённое ревью | выкл. |
| Обновление PR — новые коммиты, новые и закрытые PR | выкл. |
| Итог доработки и rebase | вкл. |
| Ошибки сервиса — только первая в серии, и одно уведомление на зависший проход | вкл. |

У репозитория могут быть свои настройки вместо общих; ошибки сервиса — только общие. Настройки личные и хранятся в UserDefaults приложения, как тема.

«Не беспокоить» на листе уведомлений (кнопка «Выключить…») или «Выключить уведомления» в меню по правому клику выключает все уведомления на 1–24 часа или до ручного включения. События за это время отмечаются как сообщённые и после включения не приходят.
