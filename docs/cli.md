# Команды CLI

Всё, что умеет окно, доступно и из терминала: окно само вызывает эти команды. Запуск — `bin/pr-reviewer <команда>` из папки проекта. `bin/pr-reviewer` создаёт `install.sh`, а без аргументов или с неизвестной командой CLI печатает краткую справку (`help`).

Ошибки команд печатаются в stderr и пишутся в журнал `~/Library/Logs/pr-reviewer/worker.log` с меткой `ERROR`: так видны и ошибки команд, которые окно запускает без терминала. Код выхода при ошибке — 1.

## Насколько команда безопасна

У каждой команды ниже стоит метка:

- **чтение** — только читает состояние, ничего не меняет;
- **данные** — меняет файлы сервиса в `~/Library/Application Support/pr-reviewer/` или `config.json`, но наружу не пишет;
- **модель** — запускает модель: тратит лимит подписки, в отчётах появляется цена;
- **Bitbucket** — публикует или меняет комментарии в PR;
- **git** — меняет ветку PR в Bitbucket (push).

Где сервис работает в фоне, команда только ставит заявку и сразу возвращается; результат смотрите командой `show` или в окне.

## Сервис

| Команда | Что делает | Метки |
|---|---|---|
| `status` | Состояние (пауза, идёт ревью, ошибка), все текущие ревью (по строке «Сейчас: …» на каждое), последний запуск и ошибка, десять последних ревью с числом замечаний по уровням | чтение |
| `run [--dry-run] [--repo <slug>] [--pr <id>] [--force]` | Один проход по открытым PR прямо в терминале. При выключенном фоновом ревью без `--force` выполняет только явные заявки из очереди | модель, Bitbucket, данные |
| `run --dry-run …` | То же, но замечания и ответы печатаются, а не публикуются, состояние не сохраняется, очередь заявок не разбирается. Модели запускаются по-настоящему, `git fetch` идёт, на время прогона фоновый проход пропускается (занят лок) | модель |
| `run-now` | Попросить launchd начать фоновый проход сейчас, не дожидаясь интервала. Кнопка ▶ в обзоре | модель, Bitbucket |
| `stop` | Прервать текущий проход — все идущие ревью во всех репозиториях — и очистить очередь явных заявок | данные |
| `pause` | Выключить фоновое ревью и сразу прервать текущий проход (как `stop`, очередь тоже очищается) | данные |
| `resume` | Включить фоновое ревью | данные |
| `sync` | Обновить список открытых PR для окна (только чтение из Bitbucket, без `git fetch`). Окно зовёт её кнопкой обновления и при открытии | данные |
| `stats` | Сравнение моделей по `stats.jsonl` и `outcomes.jsonl` (см. [stats.md](stats.md)) | чтение |
| `limits` | Обновить остатки лимитов подписок Codex и Cursor и напечатать все известные. Лимит Claude обновляется сам при каждом его запуске | данные |

`run` без `--scheduled` — это ручной проход: он не ждёт интервала. С `--scheduled` его каждую минуту вызывает launchd, и проход начинается, только если с прошлого прошло `intervalMinutes` или был запрошен `run-now`. Если другой проход уже идёт, `run` молча выходит (в терминале пишет «предыдущий запуск ещё идёт»).

## Ревью одной моделью

| Команда | Что делает | Метки |
|---|---|---|
| `review --repo <slug> --pr <id> --agent <claude\|codex\|cursor>` | Поставить явное ревью этой моделью в очередь и разбудить воркер. Работает при выключенном фоновом ревью, для черновиков, для PR вне `branchPattern` и для модели, выключенной из фона. Ревьюит голову заново, даже если уже ревьюил её. Клик по иконке модели в обзоре | модель, Bitbucket |

Повторная заявка на ту же пару «PR и модель» не дублируется. Подробнее о ревью — в [review.md](review.md).

## Настройки

Все эти команды меняют `config.json` и действуют со следующего прохода, без переустановки.

| Команда | Что делает |
|---|---|
| `interval <мин>` | Как часто фоновое ревью проверяет PR: целое число от 1 до 1440 |
| `branches <regexp>` | Какие исходные ветки PR ревьюятся фоном (регулярное выражение без учёта регистра). Остальные — только вручную |
| `ignore list [--json]` | Шаблоны файлов, которые вырезаются из диффа |
| `ignore add <шаблон>` / `ignore remove <шаблон>` | Добавить или убрать glob-шаблон, например `**/yarn.lock` |
| `agent set <claude\|codex\|cursor> [--model <id>] [--effort <уровень>\|default] [--label <название>] [--auto on\|off]` | Модель, уровень reasoning, название модели в подписи комментариев и участие в фоновом ревью |
| `agent models cursor` | Список моделей, доступных аккаунту Cursor; сохраняется в `cursor-models.json` для окна настроек |
| `token <bitbucket\|claude\|cursor> <дней\|never>` | Срок жизни токена, выбранный при выпуске; по нему окно предупреждает об истечении |

Про `agent set`:

- `--effort default` убирает уровень у Claude (CLI берёт свой по умолчанию). У Codex уровень обязателен, `default` для него — ошибка.
- У Cursor уровень reasoning — часть id модели (`grok-4.7-high`), поэтому `--effort` для него — ошибка.
- `--label` меняет текст в квадратных скобках подписи (`🤖 Generated with [Claude Opus 5.5](…)`). Маркер, по которому сервис узнаёт свои комментарии, не меняется.
- `--auto off` убирает модель из фонового ревью: в фоне она не ревьюит, не отвечает в тредах и не закрывает свои треды. Ручной запуск работает.

Все поля `config.json` — в [config.md](config.md).

## Репозитории

| Команда | Что делает | Метки |
|---|---|---|
| `repo list [--json]` | Подключённые репозитории: скачан ли клон, включено ли фоновое ревью | чтение* |
| `repo add <ссылка> [--source <путь>] [--json]` | Проверить доступ через Bitbucket API, дописать репозиторий в `config.json` и скачать служебную копию. С `--json` только подключает (клон окно качает отдельно) | данные |
| `repo clone <slug>` | Скачать служебную копию подключённого репозитория | данные |
| `repo pause <slug>` / `repo resume <slug>` | Выключить или включить фоновое ревью одного репозитория. Явные запуски работают | данные |
| `repo remove <slug>` | Отключить репозиторий и удалить его служебную копию. Отказывается, если прямо сейчас идёт ревью в этом репозитории | данные |

\* `repo list`, `repo add`, `repo clone` и любой проход убирают из `config.json` поле `source`, если такой папки больше нет (с записью в журнал).

Ссылка для `repo add` — адрес репозитория в Bitbucket (`https://bitbucket.org/<workspace>/<slug>`, SSH-адрес) или просто `workspace/slug`. `--source` — локальная копия для быстрого первого клона; без него она ищется рядом с `source` уже подключённых репозиториев.

## Доработка по замечаниям

| Команда | Что делает | Метки |
|---|---|---|
| `fix --repo <slug> --pr <id>` | Поставить доработку: rebase на целевую ветку, зависимости, правки Claude по открытым тредам и коммит, проверки, `push --force-with-lease` | модель, git |
| `fix --repo <slug> --pr <id> --rebase` | То же без правок по замечаниям | модель, git |
| `fix stop [--repo <slug> --pr <id>]` | Прервать доработку этого PR: ждущая заявка снимается, идущая останавливается. Без `--repo` и `--pr` — то, что идёт сейчас. Очередь других PR продолжается | данные |

Подробно — [fix.md](fix.md).

## Архитектурное ревью

| Команда | Что делает | Метки |
|---|---|---|
| `arch --repo <slug> --pr <id>` | Поставить архитектурное ревью в очередь. В PR ничего не публикуется | модель |

| `arch stop [--repo <slug> --pr <id>]` | Прервать ревью этого PR (ждущее или идущее); без `--repo` и `--pr` — то, что идёт сейчас. Очередь других PR продолжается | данные |

## Тестирование в браузере

Работает только для репозитория из `qa.frontend` (по умолчанию `frontend`).

| Команда | Что делает | Метки |
|---|---|---|
| `qa plan --repo <slug> --pr <id> [--note <текст>]` | Составить план тестирования; `--note` — на что обратить внимание и свои кейсы | модель |
| `qa run --repo <slug> --pr <id> [--only C1,C3] [--skip C2] [--add <кейс>]… [--note <текст>]` | Прогон по плану: тесты Vitest, для e2e — бэкенд в Docker и Playwright. `--add` можно повторять | модель |
| `qa show --repo <slug> --pr <id> [--plan] [--json]` | Отчёт последнего прогона; план — с `--plan` (или если прогона ещё не было) | чтение |
| `qa save --repo <slug> --pr <id>` | Скопировать тесты последнего прогона в вашу локальную копию репозитория (`source`), без коммита | данные |
| `qa list [--json]` | Все тестирования и их состояние | чтение |
| `qa stop [--repo <slug> --pr <id>]` | Прервать план или прогон этого PR (ждущий или идущий) и остановить тестовое окружение; без `--repo` и `--pr` — то, что идёт сейчас. Очередь других PR продолжается | данные |

Подробно — [qa.md](qa.md).

## Бэклог

| Команда | Что делает | Метки |
|---|---|---|
| `backlog list [--repo <slug>] [--all] [--json]` | Записи, ждущие разбора; `--all` — вместе с разобранными | чтение |
| `backlog export [--repo <slug>] [--all] [--json]` | То же markdown-отчётом для еженедельного разбора | чтение |
| `backlog filed <id> [задача]` | Отметить, что задача заведена | данные |
| `backlog drop <id> [причина]` | Отклонить запись | данные |
| `backlog reopen <id>` | Вернуть запись в ожидание | данные |
| `backlog learn [--repo <slug>] [--prs <N>] [--dry-run] [--background]` | Собрать в бэклог отложенные проблемы из незакрытых тредов влитых PR | модель, данные |
| `backlog triage [--repo <slug>] [--dry-run] [--background]` | Проверить по коду основной ветки, актуальны ли ждущие записи. Сам ничего не закрывает | модель, данные |
| `backlog close-stale [--repo <slug>]` | Отклонить записи, которые `triage` счёл неактуальными | данные |
| `backlog stop` | Прервать `learn` или `triage` | данные |

С `--background` задача уходит в отдельный процесс, а команда сразу возвращается; так её запускает окно. Подробно — [backlog.md](backlog.md).

## Память ревьюеров

| Команда | Что делает | Метки |
|---|---|---|
| `memory list <slug> [--json]` | Правила репозитория со срабатываниями | чтение |
| `memory add <slug> <текст>` | Добавить правило вручную | данные |
| `memory edit <slug> <id> <текст>` | Исправить правило | данные |
| `memory remove <slug> <id>` | Удалить правило | данные |
| `memory learn <slug> [--prs <N>] [--dry-run]` | Разово разобрать в память комментарии людей из последних N PR (по умолчанию 100) | модель, данные |
| `memory review <slug>` | Модель предлагает план чистки памяти; план только сохраняется | модель |
| `memory review <slug> --show [--json]` | Показать сохранённый план | чтение |
| `memory review <slug> --discard` | Удалить план | данные |
| `memory apply <slug>` | Применить план | данные |
| `memory history <slug> [--limit <N>] [--json]` | Журнал изменений памяти (по умолчанию 30 последних записей; `--json` — весь) | чтение |
| `memory restore <slug>` | Откатить последний применённый разбор | данные |

`memory learn` (без `--dry-run`), `memory apply` и `memory restore` не работают, пока идёт проход ревью: память в это время может меняться. Подробно — [memory.md](memory.md).

## Служебные команды

`fix-worker`, `arch-worker` и `qa-worker` — фоновые обработчики очередей. Их запускают `fix`, `arch` и `qa plan|run` сами; вручную вызывать не нужно.
