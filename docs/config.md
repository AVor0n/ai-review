# config.json

Настройки сервиса лежат в `config.json` в папке проекта. Это личный файл: в нём email, репозитории и локальные пути, поэтому в git он не попадает. Образец — `config.example.json`; при первом запуске `install.sh` сам копирует его в `config.json` и останавливается, пока вы не замените плейсхолдеры (`you@example.com`, `your-workspace`, `/path/to/…`).

Конфиг перечитывается при каждом запуске команды и каждом проходе, поэтому переустанавливать сервис после правки не нужно.

## Как править

- **В окне.** Частые настройки — отдельными элементами в «Настройках»: интервал, репозитории, модели, «Ветки для ревью», «Исключения из диффа», «Токены». Всё остальное — «Настройки» → «Дополнительно» → «config.json»: редактор с подсветкой и описанием поля под курсором. Перед сохранением он проверяет конфиг по схеме и не перезапишет файл, если тот изменили, пока редактор был открыт.
- **Командами** — `interval`, `branches`, `ignore`, `agent set`, `token`, `repo …` (см. [cli.md](cli.md)).
- **В VS Code.** Поле `"$schema": "./schema/config.schema.json"` включает подсказки, описания полей и подчёркивание ошибок. В окне для этого есть кнопка «Открыть в VS Code».

Схема — `schema/config.schema.json`. Неизвестные поля она запрещает.

## Верхний уровень

| Поле | Умолчание | Что значит |
|---|---|---|
| `intervalMinutes` | 15 | Как часто фоновое ревью проверяет PR, в минутах (1–1440; в окне — 1–240). Действует со следующей минуты |
| `parallelRepos` | 3 | Сколько репозиториев проход проверяет одновременно (1–10). Внутри репозитория модели работают по одной. `1` — репозитории по очереди |
| `branchPattern` | `PROJ-\d+` | Регулярное выражение для исходной ветки PR, без учёта регистра. PR с другими ветками фон не ревьюит (в обзоре у них тег «Untracked»), вручную — можно. `.` подходит к любой ветке |
| `ignorePaths` | нет исключений | Glob-шаблоны файлов, которые вырезаются из диффа перед ревью: lock-файлы, сгенерированный код, снапшоты. `**` — любое число папок. В образце уже есть типовой набор |
| `bitbucket` | обязательно | Доступ к Bitbucket, см. ниже |
| `repos` | обязательно | Подключённые репозитории, см. ниже |
| `agents` | обязательно | Модели-ревьюеры, см. ниже |
| `fix` | — | Доработка по замечаниям и rebase |
| `arch` | — | Архитектурное ревью |
| `qa` | — | Тестирование в браузере |
| `memory` | — | Память ревьюеров |

## bitbucket

| Поле | Умолчание | Что значит |
|---|---|---|
| `email` | обязательно | Email аккаунта Atlassian. От его имени публикуются комментарии; он же — имя аккаунта записи в Keychain |
| `keychainService` | обязательно | Имя записи в Keychain с API-токеном Bitbucket (обычно `pr-reviewer-bitbucket`) |
| `tokenLifetimeDays` | 365 | Срок жизни токена в днях, выбранный при выпуске; 0 — без срока. Отсчёт — от даты сохранения в Keychain. По нему окно предупреждает об истечении |

## repos

Массив репозиториев. Добавлять и отключать удобнее в настройках окна или командой `repo add` — она сама проверит доступ и заполнит поля.

| Поле | Умолчание | Что значит |
|---|---|---|
| `workspace` | обязательно | Workspace в Bitbucket |
| `slug` | обязательно | Имя репозитория |
| `remote` | обязательно | Адрес для `git clone` служебной копии (SSH) |
| `source` | — | Ваша локальная копия: с неё быстрее первый клон, в неё же `qa save` кладёт тесты. Если папки больше нет, сервис убирает поле с записью в журнал |
| `paused` | `false` | `true` — фоновое ревью репозитория выключено; явные запуски работают |

## agents

Ключи — `claude`, `codex`, `cursor`; другие схема не допускает. Модель, которой нет в `agents`, не участвует нигде.

| Поле | Умолчание | Что значит |
|---|---|---|
| `shortName` | обязательно | Имя модели в окне и в текстах комментариев |
| `marker` | обязательно | Начало подписи, по которому сервис узнаёт свои комментарии. **Не меняйте**: старые треды перестанут распознаваться как комментарии модели |
| `signature` | обязательно | Подпись под комментариями в PR. Название в квадратных скобках меняет `agent set --label` и окно при смене модели |
| `model` | обязательно | Модель CLI: `claude --model`, `codex -m`, `cursor-agent --model`. У Cursor уровень reasoning — часть имени модели |
| `effort` | по умолчанию CLI | Уровень reasoning Claude: `low`, `medium`, `high`, `xhigh`, `max` |
| `reasoningEffort` | обязательно для Codex | Уровень reasoning Codex: `low`, `medium`, `high`, `xhigh`; доступные зависят от модели |
| `repliesEffort` | `medium` | Уровень для запусков, где модель только отвечает в тредах, без ревью кода. Выше основного не поднимается. У Cursor не действует |
| `keychainService` | — | Запись в Keychain с токеном CLI для фоновых запусков: у Claude — токен `claude setup-token`, у Cursor — API-ключ. У Codex не нужен: он берёт свой вход из `~/.codex` |
| `tokenLifetimeDays` | Claude — 365, Cursor — не задан | Срок жизни токена из `keychainService`; 0 — без срока |
| `timeoutMinutes` | обязательно | Сколько ждать одно ревью этой модели |
| `auto` | `true` | `false` — модель не участвует в фоновом ревью (не ревьюит, не отвечает, не закрывает свои треды), но запускается по клику на иконку |
| `pricing` | — | Тарифы в долларах за миллион токенов: `inputPerMTok`, `cachedInputPerMTok` (без него — как обычный вход), `outputPerMTok`. Нужны Codex и Cursor, чтобы посчитать цену: их CLI её не сообщают |
| `modelPricing` | — | Тарифы по моделям, когда модель меняется в настройках (Cursor). Ключ — id модели или его начало до дефиса; быстрый режим — отдельным ключом `<модель>-fast`. Как подбирается тариф — в [stats.md](stats.md) |

## fix

Доработка PR по замечаниям и rebase всегда идут через Claude: токен и остальные поля берутся из `agents.claude`.

| Поле | Умолчание | Что значит |
|---|---|---|
| `model` | `claude-opus-5-5` | Модель Claude для доработки |
| `effort` | `high` | Уровень reasoning |
| `timeoutMinutes` | 60 | Сколько ждать один шаг модели |

## arch

| Поле | Умолчание | Что значит |
|---|---|---|
| `agent` | `claude` | Какая модель пишет отчёт: `claude`, `codex` или `cursor` |
| `model` | модель агента | Другая модель вместо выбранной в `agents` |
| `effort` | `xhigh` | Уровень reasoning; у Codex становится `reasoningEffort`, у Cursor не действует |
| `timeoutMinutes` | 60 | Сколько ждать отчёт |

## qa

| Поле | Умолчание | Что значит |
|---|---|---|
| `frontend` | `frontend` | Репозиторий фронтенда, PR которого можно тестировать |
| `backend` | `backend` | Репозиторий бэкенда для образа Docker; должен быть подключён в `repos` |
| `model` | модель `agents.claude` | Модель Claude для плана и прогона |
| `planEffort` | `high` | Уровень reasoning для плана |
| `effort` | `high` | Уровень reasoning для прогона |
| `timeoutMinutes` | 90 | Сколько ждать один этап модели |

## memory

| Поле | Умолчание | Что значит |
|---|---|---|
| `maxLessons` | 60 | Сколько правил хранить на репозиторий. При переполнении вытесняются старые автоматические; добавленные и исправленные вручную остаются |
| `agent` | `claude` | Какая модель ведёт память (разбор ответов команды и разбор памяти) и задачи бэклога: `claude`, `codex` или `cursor` |
