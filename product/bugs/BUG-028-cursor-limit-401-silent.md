# BUG-028: лимит Cursor молча устаревает — опрос получает 401

- **Статус:** закрыт
- **Серьёзность:** S3
- **Компонент:** CLI (`src/limits.mjs`), окно (`menubar/Model.swift`, `menubar/SettingsView.swift`)
- **Заведён:** 2026-10-30, qa
- **Источник:** найдено qa при проверке BUG-008 в окне

## Описание

После исправления BUG-008 окно опрашивает Codex и Cursor, если их собственное поле `at` старше 5 минут. Codex обновляется. Cursor отвечает на запрос лимита `401`. Тогда `refreshLimits` кладёт ошибку в `errors` и не трогает старое значение. Окно вывод `limits` не читает (`CLI.run(["limits"]) { _, _ in self.reload() }`), поэтому ошибку не видно нигде: ни в настройках, ни в журнале.

В «Настройках» строка Cursor показывает старый остаток с прошедшей датой сброса: «83% месяца осталось · до 30 окт.». Сброс был сегодня в 11:36 UTC. Только подсказка при наведении говорит «Обновлено N ч назад». В BUG-008 значение Cursor было 9-дневной давности; возможно, причина та же.

## Окружение

- Код 446b810, данные на 2026-10-30 ~14:00 UTC.

## Шаги воспроизведения

1. Подождать час-другой после последнего ревью Cursor.
2. Открыть «Настройки». Окно вызовет `limits`, потому что у Cursor `at` старше 5 минут.
3. Посмотреть строку лимита Cursor и `limits.json`.

## Фактический результат

`limits.json`: у Codex `at` = 13:02:51Z (обновился), у Cursor `at` = 11:09:04Z, `resetsAt` = 11:36:34Z (прошёл). В окне «83% месяца осталось · до 30 окт.», признака ошибки нет.

Тот же запрос, что делает `cursorLimits`, только без записи в `limits.json` (scratch-скрипт, токен не печатается): `HTTP 401`, тело `{code, message, details}`, `planUsage` нет.

## Ожидаемый результат

Окно не выдаёт устаревший лимит за текущий. Например, при ошибке опроса строка помечена («не удалось обновить: …») или скрыта, если дата сброса прошла. Если токен Cursor можно обновить, сервис делает это сам. Что именно показывать, решают PM и designer.

## Логи и доказательства

- Последнее успешное обновление Cursor — 11:09:04Z, через 10 секунд после ревью Cursor в 11:08:54Z (`stats.jsonl`, frontend#2797). Предположение, не проверено: токен `cursor-access-token` в Keychain живёт недолго и освежается только при запуске `cursor-agent`, поэтому лимит удаётся получить лишь сразу после ревью Cursor.
- Токен для ревью Cursor — другая запись Keychain (`pr-reviewer-cursor`), сами ревью проходят.

## Предполагаемое место в коде

- `src/limits.mjs:40-71` — `cursorLimits` берёт `cursor-access-token`, ошибка уходит в `errors` и нигде не показывается.
- `menubar/Model.swift:1760-1768` — результат `limits` игнорируется.
- `menubar/SettingsView.swift:384-392` — строка лимита не учитывает прошедший `resetsAt` и давность `at`.
