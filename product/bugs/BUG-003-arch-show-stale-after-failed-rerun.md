# BUG-003: `arch show` после неудачного перезапуска молча показывает старый отчёт

- **Статус:** передан dev
- **Серьёзность:** S4
- **Компонент:** CLI (`src/arch.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa по коду

## Описание

Если архитектурное ревью по PR уже было, а повторный запуск упал, состояние — `failed` с `error`, но `result` прошлого отчёта остаётся (`setState` сливает поля). `renderArchReport` пишет об ошибке, только если `result` нет, а плашку ставит только для `queued`/`running`. Итог: `arch show` и «Скопировать .md» в окне выдают старый отчёт без пометки, что последний запуск не удался. В окне колонна показывает треугольник, так что там ошибка видна. Для `qa show` такой случай уже обработан (`src/cli.mjs:474-475`).

## Окружение

- Сейчас в данных одно состояние (`frontend__2795`), не `failed`.

## Шаги воспроизведения

1. Есть готовый отчёт по PR.
2. Перезапустить архитектурное ревью и прервать его или дождаться ошибки.
3. `bin/pr-reviewer arch show --repo <slug> --pr <id>`.

## Фактический результат

Старый отчёт, без упоминания ошибки.

## Ожидаемый результат

Сверху строка «Последний запуск не удался: <ошибка>, ниже — прошлый отчёт», как в `qa show`.

## Предполагаемое место в коде

- `src/arch.mjs:253` и `src/arch.mjs:283` — добавить строку для `state === 'failed'` при наличии `result`.
