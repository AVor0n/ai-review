# BUG-008: лимиты Codex и Cursor не обновляются, пока работает Claude

- **Статус:** передан dev
- **Серьёзность:** S3
- **Компонент:** окно (`menubar/Model.swift`), CLI (`src/limits.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa по данным

## Описание

README: Codex и Cursor опрашиваются при открытии настроек не чаще раза в 5 минут. Окно решает, пора ли, по дате изменения всего `limits.json`. А Claude перезаписывает этот файл при каждом своём запуске (`rememberClaudeLimits` → `save`). Пока Claude ревьюит чаще раза в 5 минут или просто запускался недавно, остатки Codex и Cursor не обновляются.

## Окружение

- Данные на 2026-10-30.

## Логи и доказательства

`~/Library/Application Support/pr-reviewer/limits.json`:

```
codex:  at 2026-10-27T17:06:32Z   ← 3 дня назад
cursor: at 2026-10-21T09:29:39Z   ← 9 дней назад, resetsAt 2026-10-30T11:36 (сегодня)
claude: at 2026-10-30T03:46:29Z
```

## Шаги воспроизведения

1. Открыть «Настройки» в окне через несколько минут после любого запуска Claude.
2. Сравнить «Обновлено …» в подсказке лимита Codex и Cursor.

## Фактический результат

Остатки Codex и Cursor многодневной давности. Подсказка честно пишет «Обновлено N дней назад», но строка лимита выглядит актуальной.

## Ожидаемый результат

Codex и Cursor опрашиваются, если их собственное поле `at` старше 5 минут.

## Предполагаемое место в коде

- `menubar/Model.swift:1740-1745` — проверять `limits[codex|cursor].at`, а не дату изменения файла.
- Комментарий `menubar/Model.swift:1739` описывает именно это намерение.
