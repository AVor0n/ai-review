## Замечания

1. **Баннер «Проход ревью не продвигается» ложно висит, пока идёт долгое ревью.** Воркер пишет `heartbeat` раз в 30 с, но этот файл не даёт события в `/events` (`eventType` в `api.mjs` знает только `status.json`, `paused`, `queue`, `worker.pid`). Приложение берёт пульс из `/status` и перечитывает его только по событию `status`. Если одно ревью идёт дольше 15 минут и за это время `status.json` не меняется, приложение решит, что проход завис. Появятся оранжевый баннер с кнопкой «Прервать» и мигающий значок, хотя ревью идёт. SwiftUI смотрит дату изменения файла и такого не показывает. Проверено: пульс 20 минут назад → баннер. Записан свежий пульс, `/status` отдаёт новое время, через 40 с и после повторного открытия поповера — по-прежнему «не продвигается 21 мин». Баннер ушёл только после записи `status.json`. Таймаут моделей 40 мин; за последние 300 ревью одно шло 22 минуты. S3.
2. **После запуска приложения баннеры памяти не появляются до следующего изменения памяти.** При подключении `data.ts` читает память дважды: сначала вместе с конфигом, потом отдельным загрузчиком `memory` по `current.config`. Второй раз конфиг в ссылке ещё пустой, поэтому запросов нет, и пустая память затирает прочитанную. Проверено по сети: после перезагрузки `/memory/*` запрошена один раз, вместе с конфигом. Баннеры «переполнена» и «почти заполнена» пропали. После правки одного файла памяти они вернулись. Так пропадают все баннеры памяти: заполнение, новые правила, повреждение. Файл памяти меняется только после ревью, которое выучило правило, или после ручной правки, поэтому без баннеров можно жить днями. При переподключении после остановки API баннеры на месте: конфиг уже есть. S3.
3. **Баннер «Память повреждена» в новом поповере не появится никогда.** `GET /memory/{repo}` на битый файл отвечает 200 и `lessons: []`: `loadMemory` проглатывает признак `broken`. Приложение ждёт ошибку API и потому считает память пустой. Проверено: в файл android записан битый JSON — ответ 200, баннера нет. SwiftUI показывает красный баннер «ревью идёт без её правил». Это не только известная кнопка «Открыть в VS Code»: пропал сам баннер. Чинить в API: отдавать признак повреждения. S3.
4. **Уведомление «сервис не отвечает» повторяется каждые 30 секунд, пока сервис лежит.** Таймер уведомления зависит от `connection`, а каждая неудачная попытка подключения создаёт новый объект с тем же `since`. После первой минуты остаток времени — 0, и уведомление уходит при каждой попытке. Проверено: за 2 минуты 20 секунд простоя — четыре одинаковых уведомления, третье и четвёртое на 30-секундной паузе между попытками. Если сервис упал ночью, к утру будет больше сотни уведомлений. Кроме того, в тексте уведомления «командой ниже», а команды в уведомлении нет. S3.
5. **Порт API из настроек не читается.** `createApi` и `baseUrl` всегда берут 8765. Спецификация приложения (решение 4): «порт из настроек». Если сменить `api.port`, сервис уйдёт на новый порт, а приложение покажет «Сервис не запущен». S4.
6. **Мелкие отличия текстов от SwiftUI.** S4.
   - Архитектурное ревью: вердикт в подсказке с маленькой буквы («Архитектурное ревью: стоит обсудить»). В SwiftUI — «Стоит обсудить».
   - QA: в подсказке готового прогона «прошло», «пропущено». В SwiftUI — «прошёл», «пропущен». Кейс без статуса приложение считает неподтверждённым, SwiftUI его не считает.
   - Баннер зависания: время «последней записи в журнале» — время пульса. SwiftUI берёт более раннее из пульса и изменения журнала.
7. **Баннер «Сервис не запущен» появляется через 2,5 с, а не через 5.** Вторая неудачная попытка идёт после паузы 2,5 с. Проверено: API остановлен в 01:24:03, в 01:24:06 баннер уже есть. Спецификация: «около 5 с, чтобы не мигать при запуске». Только наблюдение.
8. **Спецификация поповера и SwiftUI расходятся в цвете баннера токена.** Для «токен истекает» спецификация называет `--alert` (оранжевый). Приложение, как и SwiftUI, показывает жёлтый `--warning`. Вопрос дизайнеру, не ошибка приложения.

Не проверено:
- Вид на экране и Windows — проверяет пользователь.
- Сборка Tauri и её поведение: положение у значка, закрытие по клику мимо, автозапуск, системный диалог, настоящие уведомления.
- «Подключить…» при пустом списке репозиториев — проверено только по коду.
