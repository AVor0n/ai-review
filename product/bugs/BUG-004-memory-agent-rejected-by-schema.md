# BUG-004: `memory.agent` читается кодом, но запрещён схемой конфига

- **Статус:** передан dev
- **Серьёзность:** S3
- **Компонент:** конфиг (`schema/config.schema.json`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa

## Описание

README документирует `memory.agent` (модель для памяти и бэклога, по умолчанию Claude), код его читает: `src/memory.mjs:172`, `src/memory-review.mjs:137`, `src/backlog-jobs.mjs:63`. Но в схеме у `memory` стоит `additionalProperties: false` и описан только `maxLessons`. Редактор config.json в окне проверяет конфиг по схеме и откажется сохранять конфиг с `memory.agent`, VS Code подчеркнёт ключ как ошибку. Сменить модель памяти можно только правкой файла в обход проверки.

## Окружение

- `config.json` сейчас: `"memory": { "maxLessons": 60 }`

## Шаги воспроизведения

1. «Настройки» → «Дополнительно» → «config.json».
2. Добавить в `memory` поле `"agent": "codex"`, сохранить.

## Фактический результат

Ожидается отказ сохранения: «неизвестное поле». Вывод сделан по схеме, в окне не проверял: это меняло бы `config.json`.

## Ожидаемый результат

Поле принимается, у него есть описание; значения — id моделей из `agents`.

## Предполагаемое место в коде

- `schema/config.schema.json:211-221` — добавить `agent` (`enum`: `claude`, `codex`, `cursor`, описание «модель для памяти, разбора памяти и бэклога; по умолчанию claude»).
