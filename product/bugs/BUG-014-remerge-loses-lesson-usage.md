# BUG-014: повторная склейка правил памяти теряет срабатывания первой склейки

- **Статус:** закрыт
- **Серьёзность:** S4
- **Компонент:** CLI (`src/memory-review.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa по коду

## Описание

README: склеенное правило наследует срабатывания исходных (`source.mergedFrom`). При склейке `mergedFrom` перезаписывается id текущей склейки: `{ ...source, mergedFrom: action.ids }`. Если одно из склеиваемых правил само было склеено раньше, его `mergedFrom` пропадает. Псевдонимы в `lessonUsage` разворачиваются на один уровень. Итог: после второго разбора памяти счётчики срабатываний и исходов правил из первой склейки исчезают, и правило выглядит как «ни разу не сработало» — кандидат на удаление при следующем разборе.

Ещё один случай: если ни у одного склеиваемого правила нет `source` (все добавлены вручную), `mergedFrom` не сохраняется вовсе.

## Шаги воспроизведения

На изолированной копии данных (`HOME=<scratch>`), с разрешения пользователя (разбор тратит модель):

1. Правила A1, A2 со срабатываниями; разбор склеивает их в B.
2. Следующий разбор склеивает B и C в D.
3. `memory list <slug> --json` — `usage` у D.

## Фактический результат

У D только срабатывания B и C, срабатываний A1 и A2 нет.

## Ожидаемый результат

`mergedFrom` у D включает A1, A2, B, C (или псевдонимы разворачиваются транзитивно).

## Предполагаемое место в коде

- `src/memory-review.mjs:202` — объединять `mergedFrom` исходных правил.
- `src/memory-review.mjs:31-32` — транзитивное разворачивание.
