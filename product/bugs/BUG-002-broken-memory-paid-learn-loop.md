# BUG-002: при повреждённом memory/<slug>.json модель памяти запускается и тратит деньги на каждом проходе

- **Статус:** передан dev
- **Серьёзность:** S3
- **Компонент:** CLI (`src/memory.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** сверка README с кодом (техпод), подтверждено qa по коду

## Описание

README: если файл памяти повреждён, «сервис его не перезаписывает… новые правила не сохраняются». Но `learn` проверяет это только при сохранении, то есть уже после платного запуска модели. Если модель нашла хоть одно правило, `addLesson` → `saveMemory` бросает ошибку, `learn` возвращает `[]`, и обсуждения остаются неразобранными. На следующем проходе всё повторяется, и так пока файл не починят. Модель при этом получает пустой список известных правил (`loadMemory` возвращает `[]`), так что находит правила чаще обычного.

## Окружение

- Сейчас не проявляется: все файлы памяти исправны. Возникает после ручной правки файла (кнопка «Открыть в VS Code»).

## Шаги воспроизведения

Только на изолированной копии данных (`HOME=<scratch>`) и с разрешения пользователя: нужен запуск модели.

1. Испортить `memory/<slug>.json` (например, удалить `"at"` у одного правила).
2. Дождаться ответа человека в треде модели в этом репозитории.
3. Несколько проходов подряд.

## Фактический результат

На каждом проходе: запись `memory-learn` с ценой в `spend.jsonl`, затем `ERROR … не удалось обновить память — память <slug> повреждена …; изменения памяти не сохранены`.

## Ожидаемый результат

При повреждённой памяти `learn` не запускает модель: одна запись в лог, обсуждения ждут исправления файла.

## Логи и доказательства

Проверено по коду (`src/memory.mjs:168-196`): `runStructured` и `appendSpend` идут до `addLesson`. Проверки `readMemory(slug).broken` до запуска нет.

## Предполагаемое место в коде

- `src/memory.mjs:171-173` — добавить ранний выход, если `readMemory(repo.slug).broken`.
- `src/memory.mjs:58-60` — здесь сейчас срабатывает проверка, уже после траты.
