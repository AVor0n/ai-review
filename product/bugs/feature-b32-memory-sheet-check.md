## Замечания

1. **Ошибки правки, удаления и добавления правила нигде не видны.** `add`, `save` и `remove` в `MemorySheet.tsx` не смотрят на ответ API. Поле нового правила очищается ещё до запроса. SwiftUI при ошибке CLI ставит `syncError`, и обзор показывает баннер «Не удалось выполнить команду». Проверено: папка памяти копии сделана только для чтения. «Добавить» → API ответил ошибкой `EACCES`, правила в списке нет, введённый текст пропал, ни в листе, ни в обзоре ошибки нет. Удаление в тех же условиях — тоже без следа. Бывает редко: правило успели удалить или вытеснить, ошибка записи на диск. S4.
2. **Повреждённую память по-прежнему не открыть из обзора.** У баннера «Память … повреждена» нет кнопок. Карточку повреждённого файла видно, только если файл испортился при открытом листе. В SwiftUI у баннера была кнопка «Открыть в VS Code». Отсутствие этой кнопки уже известно с B-30. Теперь в приложении есть `open_in_code`, и её легко вернуть. Только наблюдение.

Не проверено:
- **«Изучить».** Кнопка запускает `memory learn`: он читает комментарии PR из Bitbucket и вызывает модель. Проверены только вид карточки и выбор числа PR.
- **Подсветка слов в сравнении со SwiftUI на одних и тех же правилах.** Есть тесты `wordDiff.test.ts`, а на копии подсветка выглядит разумно. Рядом со SwiftUI не сравнивал: старое окно снять не удалось, как и в B-30.
- **Windows, вид на экране, настоящий системный диалог и VS Code** — за пользователем.
