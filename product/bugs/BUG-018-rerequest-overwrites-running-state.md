# BUG-018: повторная заявка из терминала затирает состояние идущей задачи этого PR

- **Статус:** отложен
- **Серьёзность:** S4
- **Компонент:** CLI (`src/fix.mjs`, `src/arch.mjs`, `src/qa.mjs`)
- **Заведён:** 2026-10-30, qa
- **Источник:** техпод при написании docs/, подтверждено qa по коду

## Описание

`requestFix`, `requestArch`, `requestQaPlan` и `requestQaRun` сразу пишут состояние «в очереди», даже если по этому PR задача уже идёт. У доработки к тому же стирается `report`. Окно больше не видит `running`: пропадают ход работы и «Прервать». Когда идущая задача закончится, она перезапишет состояние, а затем выполнится и вторая заявка, то есть повтор той же работы. Окно такие повторы не допускает (кнопки заблокированы или открывают отчёт), поэтому сценарий возможен только из терминала.

## Шаги воспроизведения

С разрешения пользователя:

1. `bin/pr-reviewer qa run --repo frontend --pr <id>`, дождаться «running».
2. Повторить `qa plan` по тому же PR.

## Фактический результат

Состояние `planning-queued` поверх идущего прогона, в окне нет «Прервать» и хода прогона.

## Ожидаемый результат

Отказ: «по PR уже идёт <задача>», либо заявка встаёт в очередь, не трогая текущее состояние.
