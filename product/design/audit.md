# Аудит UI PR Reviewer по Apple HIG

Дата: 30.10.2026. Дизайнер. Основа — `product/design/hig.md` (там правила, числа и ссылки на HIG; здесь в скобках указан раздел).
Смотрел код `menubar/*.swift` и `assets/make-icon.swift`; приложение вживую не запускал, поэтому вид экранов и контраст оценены по коду. После правок нужна проверка на экране, в тёмной теме и с Increase Contrast.

Важность: **P1** — доступность, читаемость или поведение платформы сломаны; **P2** — заметно «не по-маковски» или несогласованно; **P3** — шлифовка.

Примечание: `Tokens.swift` — это API-токены (Keychain), а не дизайн-токены. Визуальные токены (цвета, контролы) лежат в `Theme.swift`.

---

## Коротко

Приложение аккуратное и последовательное внутри себя: одинаковые баннеры, единая сетка отступов 16/12, моноширинные цифры, подсказки `.help` у большинства иконок, хорошие пустые состояния (`ContentUnavailableView`), продуманная палитра графиков. Главная проблема — оно сознательно построено как **iOS-приложение внутри поповера**: поповер 780×600 со всем приложением, самодельный iOS-сегмент вместо навигации, iOS-цвета фона, зелёные переключатели, своя настройка темы. На Mac это ломает ожидаемое поведение (нет окна, ⌘,, ⌘W, сайдбара, нормальной работы с клавиатурой) и отключает часть системных адаптаций (desktop tinting, Increase Contrast, акцентный цвет). Вторая большая тема — **доступность**: в SwiftUI-коде нет ни одного `accessibility*`-модификатора, фокус клавиатуры выключен, состояние моделей передаётся только цветом.

### Главные пункты для бэклога

| # | Что | Важность |
|---|---|---|
| A1 | Вынести приложение из поповера в обычное окно с сайдбаром; значок в строке меню — компактная сводка и меню | P1 |
| A2 | Настройки — в отдельное окно Settings (⌘,), убрать вкладку «Настройки» | P1 |
| A3 | Вернуть клавиатурный фокус и сделать самодельные контролы доступными для VoiceOver | P1 |
| A4 | Состояние моделей и статусы не только цветом; кликабельные зоны ≥ 20×20 pt | P1 |
| A5 | Перейти с хардкод-цветов `Theme` на семантические цвета macOS | P2 |
| A6 | Убрать свою настройку темы | P2 |
| A7 | Заменить самодельный `SegmentedPicker` на системный `Picker(.segmented)` | P2 |
| A8 | Учесть Reduce Motion в анимациях значка и строк | P2 |
| A9 | Иконка приложения под macOS 26 (Icon Composer, без нарисованной плитки и тени) | P2 |
| A10 | Тексты: английские теги, регистр заголовков секций, многоточия, «Отмена» | P3 |

Предлагаемый порядок: A3 + A4 + A8 (доступность, точечные правки) → A5 + A6 + A7 (тема и контролы, затрагивают `Theme.swift`) → A1 + A2 (перестройка навигации, самая крупная; нужен макет и решение PM) → A9, A10.

## 1. Архитектура: строка меню, окно, навигация

### A1. Всё приложение живёт в поповере — P1
- Где: `MainWindow.swift:53` (`.frame(width: 780, height: 600)`), `MainWindow.swift:66-76` (NSPopover), `main.swift:211-227` (левый клик открывает поповер).
- HIG (§1, §7 Popovers): по клику на menu bar extra — меню; поповер — только для небольшого объёма. Сейчас в поповере пять разделов, графики, таблицы, листы поверх листов. Поповер нельзя переместить, изменить размер, свернуть, переключиться на него через ⌘\`, держать открытым рядом с браузером; закрывается при клике в другое приложение (свой монитор `MainWindow.swift:125-139`), а листы при закрытии приходится сбрасывать синтетическим Esc (`MainWindow.swift:100-123`) — это и есть симптом того, что компонент используется не по назначению.
- Предложение:
  1. **Главное окно** «PR Reviewer»: `NavigationSplitView` с сайдбаром (`List(.sidebar)`): Обзор, Бэклог, Статистика, Журнал — с SF Symbols (`list.bullet.rectangle`, `tray.full`, `chart.bar.xaxis`, `doc.text`). Заголовок окна — название раздела. Окно изменяемое, мин. 760×520, размер и раздел запоминаются. Действия раздела (обновить, запустить, прервать, экспорт) — в тулбар окна, у каждого `.help` и дубль в меню.
  2. **Значок в строке меню**: левый клик — меню (или компактный поповер ~320 pt шириной, если PM решит, что меню мало): строка статуса («Идёт ревью repo #123 · Claude» / «Ожидание · через 7 мин»), важные проблемы (зависание, ошибка, токен), счётчик PR без ревью, пункты «Проверить сейчас», «Прервать ревью», «Открыть PR Reviewer» (⌘O), «Настройки…» (⌘,), меню уведомлений, «Выйти» (⌘Q).
  3. Когда окно открыто — `NSApp.setActivationPolicy(.regular)` (появляется в Dock и ⌘Tab, получает нормальную строку меню с «Правка», «Вид», «Окно»); когда закрыто — обратно `.accessory`. Это убирает и обходной путь с невидимым меню «Правка» (`main.swift:28-51`).
- Это меняет продукт (как пользователь открывает приложение), поэтому сначала решение PM и пользователя; макет подготовлю после согласования.

### A2. Настройки — вкладка внутри поповера — P1
- Где: `MainWindow.swift:12, 50`, весь `SettingsView.swift`.
- HIG (§5): настройки открываются пунктом «Настройки…» и ⌘,, в отдельном окне с панелями в тулбаре; заголовок окна — имя панели; открывается последняя панель.
- Предложение: сцена `Settings` (или своё окно с тем же поведением), панели: «Основные» (фоновое ревью, интервал, уведомления), «Репозитории», «Модели», «Доступы» (токены), «Дополнительно» (шаблон веток, исключения из диффа, config.json). Содержимое панелей — `Form { … }.formStyle(.grouped)`: это нативный вид Системных настроек, он сам даёт подписи, сноски, выравнивание и корректные цвета. Переходы из обзора («Обновить…» у токена, «Проверить правила» у памяти) открывают окно настроек на нужной панели.

### A1a. Меню значка — только уведомления и выход — P2
- Где: `main.swift:53-76`, `main.swift:211-221` (правый клик).
- HIG (§1): меню — основной способ; функции значка нужно дублировать в другом месте. Сейчас «Проверить сейчас», «Прервать», переход к PR — только в поповере, а меню по правому клику почти пустое.
- Предложение: единое меню по любому клику (см. A1.2), в нём помимо уведомлений и «Выйти» (⌘Q уже есть) — «Проверить сейчас», «Прервать ревью», «Открыть PR Reviewer», «Настройки…» (⌘,).

### A1b. Значок строки меню: цветная подкраска и самодельная анимация — P2
- Где: `main.swift:131-170` (`contentTintColor = .systemOrange/.systemRed`), `main.swift:107-121` (вращение таймером 20 кадров/с), `main.swift:183-199` (мигание 6 с), `AgentIcons.swift:57-82` (глиф 16×16).
- HIG (§1, §13): значок шаблонный, система красит его сама; движение должно уважать Reduce Motion. Цветной значок при зависании/ошибке допустим как исключение (так делают системные индикаторы), но мигание и постоянное вращение игнорируют Reduce Motion.
- Предложение: при `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` — без вращения и мигания: статичный глиф модели плюс маленькая точка-бейдж. Цвет оставить только для «зависло» и «ошибка». Размер глифа 16 pt — в норме.

## 2. Доступность

### A3. Клавиатурный фокус выключен глобально — P1
- Где: `MainWindow.swift:56` (`.focusEffectDisabled()` на корне).
- HIG (§13 Keyboards, Focus): всё основное доступно с клавиатуры; фокус — системное кольцо. Комментарий объясняет причину — поповер ставит фокус на первый контрол. Это проблема поповера (A1), а не повод отключать фокус всем.
- Предложение: убрать модификатор; в окне начальный фокус — на списке PR (`.defaultFocus`) или ни на чём. Проверить проход Tab по всем экранам с включённым «Навигация с клавиатуры».

### A3a. Самодельные контролы не видны VoiceOver — P1
- Где: во всём `menubar/` нет ни одного `accessibilityLabel/Value/AddTraits`. Конкретно:
  - `Theme.swift:18-62` `SegmentedPicker` — набор plain-кнопок: VoiceOver не знает, что это группа выбора и какой сегмент выбран.
  - `AgentIcons.swift:107-151` `AgentReviewButton` — кнопка из нарисованной фигуры без текста: VoiceOver прочитает «кнопка».
  - `FixViews.swift:36-55`, `ArchViews.swift:33-60`, `QaViews.swift:81-…` — иконки без меток.
  - `OverviewView.swift:365-381` — заголовок репозитория, сворачивающий секцию, без состояния «развёрнуто/свёрнуто».
  - `StatsView.swift` — графики без описаний марок.
- Предложение: для каждой кнопки-иконки `.accessibilityLabel` (то же, что первая фраза `.help`) и `.accessibilityValue` для состояния («ревью актуально», «на старом коммите»); сегменты — системный Picker (A7) или `.accessibilityAddTraits(.isSelected)` + `.accessibilityElement(children: .contain)`; свёртку секций — `DisclosureGroup` или `.accessibilityAddTraits(.isButton)` + value «развёрнуто». Для графиков — `accessibilityLabel/Value` у марок и текстовый вывод над графиком.

### A4a. Состояние модели передаётся только цветом и прозрачностью — P1
- Где: `AgentIcons.swift:116-122`: нет ревью/в очереди — серый 40 %, старый коммит — цвет модели 45 %, актуально — полный цвет.
- HIG (§10, §13): цвет не единственный носитель смысла. Различить «старый коммит» и «актуально» по прозрачности трудно, а серый с прозрачностью 0.4 не даёт нужного контраста 3:1 для иконок.
- Предложение: три визуально разные формы, цвет — дополнительно. Например: нет ревью — контур глифа `.tertiary`; старый коммит — глиф цвета модели + маленькая точка-«устарело» (оранжевая, 5 pt) в правом верхнем углу; актуально — глиф цвета модели + галочка-бейдж или без бейджа; в очереди — `clock`-бейдж; идёт — вращение (с учётом Reduce Motion — пульсирующий бейдж). Детальная спецификация — после согласования A1, потому что строка PR может перестроиться.

### A4b. Кликабельные зоны меньше минимума — P1
- Где: крестики баннеров 18×18 (`OverviewView.swift:245, 285`), кнопки моделей 20×20 (`AgentIcons.swift:144`) — на грани, иконки-кнопки строки PR 22×22 (`FixViews.swift:48`, `ArchViews.swift:55`), ссылки-кнопки в баннерах — только по тексту.
- HIG (§13): на Mac по умолчанию 28×28, минимум 20×20; вокруг элементов без рамки ~24 pt свободного места. В строке PR сейчас 6–8 иконок по 20–22 pt с интервалом 2–10 pt (`OverviewView.swift:418-420`).
- Предложение: крестики — 20×20 минимум (лучше 24×24); иконки строки — кликабельная зона 24×24 при видимом глифе 15–16 pt, интервал между соседями ≥ 4 pt; группу моделей отделить от остальных иконок 12 pt.

### A4c. «Неактивное» через прозрачность вместо `.disabled` — P1
- Где: `SettingsView.swift:74` (`IntervalRow` 45 % при паузе), `SettingsView.swift:278` (тумблер репозитория 45 % при паузе — при этом остаётся кликабельным), `FixViews.swift:52`, `ArchViews.swift:54`, `OverviewView.swift:480` (черновики 45 %).
- HIG (§7, §13): недоступный контрол — системное состояние disabled (оно же озвучивается VoiceOver как «недоступно»). Вторичный текст под прозрачностью 45 % падает ниже 4.5:1.
- Предложение: в настройках — `.disabled(model.isPaused)` вместо opacity, пояснение оставить в сноске. Для черновиков — не гасить всю строку, а поставить тег «Черновик» и `.secondary` для заголовка (контраст сохраняется).

### A8. Анимации без учёта Reduce Motion — P2
- Где: `AgentIcons.swift:137-142` (вращение глифа в строке), `main.swift:107-121, 183-199` (значок), `Theme.swift:46` и `OverviewView.swift:26` (анимации переключения — допустимо, они короткие).
- Предложение: `@Environment(\.accessibilityReduceMotion)`; при включённом — без вращения, состояние «идёт» показывать `ProgressView().controlSize(.mini)` или статичным бейджем.

### Мелкий текст и символы < 10 pt — P2
- Где: `OverviewView.swift:370`, `BacklogView.swift:287`, `QaViews.swift:488` (шеврон 9 pt), `StatsComponents.swift:48` (шеврон 8 pt), `LogView.swift:74` (точка 4 pt — декоративная, допустимо, но скрыть от VoiceOver).
- HIG (§9): минимум 10 pt. Текста меньше 10 pt нет — хорошо. Шевроны — заменить системными: `DisclosureGroup` для секций, стандартный индикатор `Menu` для фильтров.

## 3. Цвет и тема

### A5. Цвета фона и поверхностей захардкожены под iOS — P2
- Где: `Theme.swift:9-14` (`background` = iOS systemGroupedBackground, `card`, `track`, `thumb`, `separator`, `hover` — числами RGB), используется во всех экранах.
- HIG (§10): системные цвета не хардкодить; брать семантические. Последствия: не работает desktop tinting (графитовый акцент), Increase Contrast не усиливает разделители и подложки, неактивное окно не приглушается, при будущих изменениях системы цвета «уплывут».
- Предложение (соответствие для dev):

| Сейчас | Заменить на |
|---|---|
| `Theme.background` | фон окна: `Color(nsColor: .windowBackgroundColor)`; в `Form(.grouped)` фон даёт система |
| `Theme.card` | `Color(nsColor: .controlBackgroundColor)` или секции `Form(.grouped)`/`GroupBox` |
| `Theme.separator` | `Color(nsColor: .separatorColor)` (или `Divider()`) |
| `Theme.track` | `Color(nsColor: .quaternaryLabelColor)` / `.fill.quaternary` |
| `Theme.thumb` | уйдёт вместе с `SegmentedPicker` (A7) |
| `Theme.hover` | `Color(nsColor: .quaternaryLabelColor).opacity(0.5)`; для выделенной строки — `selectedContentBackgroundColor` |

  `RowDivider` (`Theme.swift:103`) с толщиной `1/displayScale` можно оставить, но красить `separatorColor`.

### A6. Своя настройка темы — P2
- Где: `SettingsView.swift:19, 53-59`, `Theme.swift:149-186` (`AppAppearance`), `MainWindow.swift:82-92`, `QaViews.swift:931`, `main.swift:217`.
- HIG (§5, §10): «Avoid offering an app-specific appearance setting» — человек уже выбрал тему в системе, включая «Авто».
- Предложение: убрать строку «Тема» и `AppAppearance`. В окне (A1) тема наследуется сама. Проблема из комментария `Theme.swift:169-171` (поповер берёт оформление строки меню, а не системы) исчезает вместе с поповером.
- Продуктовое решение (убрать настройку, которой кто-то может пользоваться) — согласовать с PM.

### Зелёные переключатели — P2
- Где: `SettingsView.swift:67, 276` (`.tint(.green)`), также `SettingsView.swift:424, 698, 736`.
- HIG (§10): на Mac переключатели и выделение красятся акцентным цветом пользователя; зелёный тумблер — iOS-идиома. Плюс зелёный уже значит «успех/одобрено» в обзоре — один цвет, два смысла.
- Предложение: убрать `.tint(.green)`; в строках формы — `.controlSize(.mini)` (HIG §7).

### Цвета баннеров и статусов — P3
- Где: `OverviewView.swift:191, 216, 252, 293, 321, 346`, `BacklogView.swift:158-248`, `QaViews.swift:308, 324, 736`.
- Подложки `color.opacity(0.1–0.12)` поверх собственного фона — непрозрачны к desktop tinting и не усиливаются Increase Contrast; жёлтая подложка при светлой теме почти не видна.
- Предложение: оставить приём, но проверить с Increase Contrast; для баннеров-предупреждений добавить тонкую обводку того же цвета 1 pt `opacity(0.3)` — граница будет видна в любом режиме. Иконка + заголовок уже дублируют смысл цвета — хорошо.

### Цвет статуса в шапке обзора — P3
- Где: `OverviewView.swift:111-113` — точка 7 pt синяя/оранжевая/зелёная.
- Смысл дублирован текстом рядом — нарушения нет. Но зелёный «ожидание» и синий «идёт» лучше связать с формой: SF Symbols `circle.fill` → `arrow.triangle.2.circlepath` (идёт), `pause.circle.fill` (пауза), `checkmark.circle.fill` (ожидание), как в значке строки меню.

### Цвета моделей — P3
- Где: `AgentIcons.swift:96-104` — фирменные цвета без варианта для Increase Contrast; оранжевый Claude на белом ~3:1 — для иконки достаточно, для текста нет. Использовать только для глифов, не для текста.

### Палитра графиков — без замечаний
- `Theme.swift:190-221` (`ChartColors`): проверенная палитра с вариантами для тёмной темы и стабильным закреплением цвета за сущностью. Хорошо. Добавить: в легенде и подсказках — подписи, не только цвет (Swift Charts делает это сам при `foregroundStyle(by:)`, `StatsView.swift:836-882`, — нужно проверить, что ключевые значения видны без наведения).

## 4. Контролы

### A7. Самодельный сегментный контрол вместо системного — P2
- Где: `Theme.swift:18-62`; используется для навигации (`MainWindow.swift:30`) и ещё 13 раз (`BacklogView.swift:43`, `LogView.swift:21`, `QaViews.swift:221, 979`, `SettingsView.swift:56, 747, 1184, 1338`, `StatsView.swift:138, 200, 233, 263`).
- HIG (§7): для переключения видов в основной области окна — tab view/сайдбар, а не сегменты; сегменты — для 2–7 вариантов в тулбаре или инспекторе. Самодельный контрол: без клавиатуры (стрелки), без VoiceOver, не реагирует на акцентный цвет, Increase Contrast и неактивное окно, бейдж-счётчик 10 pt внутри сегмента не предусмотрен системой.
- Предложение: навигацию — сайдбаром (A1); остальные — `Picker(…).pickerStyle(.segmented)`; переключатель «Все / Ждут разбора» (`BacklogView.swift:43`) и «Все записи / Ошибки» (`LogView.swift:21`) — в тулбар окна как segmented picker или фильтр. Скорость воспроизведения в QA (`QaViews.swift:979`) — `Picker(.menu)`.

### Кнопки-ссылки вместо кнопок — P3
- Где: баннеры (`OverviewView.swift:185-188, 237-240, 276-279, 311-318, 340-343`), `LogView.swift:23-31`, `BacklogView.swift:46-63`, кнопка «Включить» в шапке (`OverviewView.swift:119-122`).
- HIG (§7): на Mac действие — push button; текст акцентного цвета читается как ссылка. В баннерах это ещё и маленькая кликабельная зона.
- Предложение: в баннерах — `Button(...).buttonStyle(.bordered).controlSize(.small)`, деструктивное «Прервать» — `role: .destructive`. Действия над списком (Разобрать, Скопировать .md, Открыть файл) — в тулбар окна.

## 8. Иконка приложения

### A9. Иконка нарисована по сетке Big Sur — P2
- Где: `assets/make-icon.swift:44-68` — рисует плитку 824 pt с радиусом 185, обводкой и тенью внутри холста 1024.
- HIG (§15): в macOS 26+ система сама маскирует иконку и добавляет эффекты Liquid Glass; нужно квадратный холст без своей плитки, тени и бликов, лучше слоями в Icon Composer (фон — синий градиент, передний план — глиф PR и галочка). Иконка с уже нарисованной плиткой в macOS 26 попадает в серую «подложку» и выглядит меньше соседей. Также нет вариантов dark/tinted.
- Предложение: подготовлю слои (фон + глиф PR + бейдж-галочка) в SVG; dev собирает `.icon` в Icon Composer. Значок строки меню не затрагивается.
