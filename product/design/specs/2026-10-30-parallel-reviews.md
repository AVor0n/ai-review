# Спецификация: несколько ревью одновременно

Дата: 30.10.2026, дизайнер. К задаче «Параллельное ревью» из очереди dev: одновременно идут ревью разных репозиториев, до трёх; внутри репозитория модели по-прежнему по очереди.

Макет был снимками окна SwiftUI (`product/design/mockups/2026-10-30-parallel-reviews.html`); окна больше нет, макет удалён перед открытием репозитория (#35). **Пользователь выбрал вариант A** (одна строка) 30.10.2026. Вариант B описан в конце для истории, его не делаем.

## Что меняется

Сейчас окно знает об одном текущем ревью: `status.current`. После правки текущих ревью может быть несколько, и это видно в трёх местах:

1. шапка обзора;
2. меню по правому клику;
3. значок в строке меню и его подсказка.

Строки PR не меняются: значок модели и так вращается у каждого PR, где идёт ревью.

При одном текущем ревью всё выглядит как сейчас.

## Данные от сервиса

Окну нужен список текущих ревью вместо одного `current`, например `running: [{ repo, pr, agent, role, startedAt }]`, упорядоченный по `startedAt`. Формат — на усмотрение dev.

## 1. Шапка обзора (вариант A)

Где: `OverviewView.swift`, `statusBar` / `headline`.

| Сколько ревью | Вид |
|---|---|
| 0 | как сейчас |
| 1 | как сейчас: «Идёт ревью frontend #2828 · Claude» |
| 2–3 | «Идут ревью:» и по каждому ревью: значок модели и «frontend #2828», между ревью « · » |

Значок модели в статусе:
- `AgentMark` 11×11 цветом модели (`AgentMark.color`), без вращения: вращение уже есть в строках PR;
- между значком и текстом 3 pt, между ревью — разделитель « · » цветом `.tertiary`.

Имя репозитория — короткое, без `acme-`, как в подсказке значка строки меню (`shortRepo` в `main.swift`). Порядок — по времени начала.

Шрифт и цвет — как у текущего статуса: 12 pt, `.secondary`, `lineLimit(1)`. Если строка не помещается, обрезается хвост статуса. Капсулы лимита и «только вручную» справа не сжимаются (как в спецификации «почему нет ревью»).

Подсказка `.help` на статусе — по строке на ревью:
```
frontend #2828 «Экспорт заказа в PDF» · Claude, первым
backend #2058 «Миграция таблицы скидок» · Cursor, первым
android #764 «Push-уведомления о доставке» · Claude, следом
```

Кнопка ■ справа при нескольких ревью: подсказка «Прервать все ревью и очистить очередь». Действие то же (`stop`).

Точка слева остаётся синей.

## 2. Меню по правому клику

Где: `main.swift`, `rebuildMenu()`.

При одном ревью — как сейчас. При нескольких:
- первая серая строка «Идут N ревью:» (N = 2 или 3; «ревью» не склоняется);
- под ней по серой строке на каждое ревью: «frontend #2828 · Claude (первым)», слева цветной значок модели 12×12 (`NSMenuItem.image`, картинка из `AgentMark`, не шаблон);
- «Прервать ревью» → «Прервать все ревью». Прерывать отдельный репозиторий в эту задачу не входит;
- если одновременно идёт доработка, её строка «Идёт доработка · Claude» ставится последней в блоке статуса.

Остальное меню без изменений.

## 3. Значок в строке меню и подсказка

Где: `main.swift`, `refreshIcon()`.

- Вращается значок модели того ревью, что началось раньше всех. Когда оно закончится — значок следующего по времени начала. Если значок модели сменился, вращение начинается заново, без плавного перехода.
- Число справа от значка (PR без ревью) — как сейчас.
- Подсказка при нескольких ревью:
  ```
  PR Reviewer: идут 3 ревью
  frontend #2828 · Claude (первым)
  backend #2058 · Cursor (первым)
  android #764 · Claude (следом)
  PR без ревью на текущем коммите: 4
  ```
  Строки про PR без ревью, важные замечания и уведомления — как сейчас, после списка ревью.

## Что не меняется

- Баннер «проход завис» — про весь проход, как сейчас.
- Строки PR, значки моделей, бейджи и капсулы.
- Ручной запуск по значку модели.

## Вариант B (не выбран)

Вместо одной строки — список под шапкой:
- первая строка «Идут 3 ревью» (точка, капсулы и кнопки — как в A);
- под ней по строке на ревью, отступ слева 15 pt, 11 pt: значок модели 11×11, «frontend #2828» `.primary`, название PR `.secondary` с обрезкой, «· Claude, первым» `.tertiary`;
- подсказка на статусе не нужна, всё видно сразу.

Минус B: шапка вырастает на 54 pt, и список PR сдвигается каждый раз, когда ревью начинается или заканчивается.

## Проверка

По коду, на подставленном `status.json` с 1, 2 и 3 текущими ревью. В каждом случае смотрим шапку, меню и подсказку значка.
