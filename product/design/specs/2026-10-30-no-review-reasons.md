# Спецификация: почему у PR нет ревью

Дата: 30.10.2026, дизайнер. Идея support и qa, принята PM. Пользователь одобрил подсказки и выбрал для лимита и «только вручную» вариант 6: капсулы в шапке и бейдж на значке.

Макеты: `product/design/mockups/2026-10-30-no-review-reasons.html`, картинки в папке рядом. Открывать через preview «mockups» (`.claude/launch.json`), адрес `http://localhost:8765/2026-10-30-no-review-reasons.html`.

## Что меняется

Серый «0» в счётчике и серый значок модели сейчас выглядят одинаково, почему бы ревью ни было. После правки:

1. **Подсказка у серого «0»** называет причину для всего PR.
2. **Подсказка у значка модели** называет причину для этой модели.
3. **Заголовок секции репозитория**, если у него выключено фоновое ревью, — пометка «фоновое ревью выключено».
4. **Капсулы в шапке обзора** для моделей с исчерпанным лимитом или «только вручную».
5. **Бейдж 8 pt на значке модели** в строках PR — для тех же двух состояний.
6. **Другая подсказка у зелёной галочки**, когда ревью пропущено: в диффе только исключённые файлы или он пуст.

Остальная строка PR не меняется: теги Draft и Untracked, цвета и прозрачность значков моделей, зелёная галочка (d4f385c).

## 1. Подсказка у серого «0»

Где: `OverviewView.swift`, `threadsCounter`, ветка `pr.threads == 0` без `reviewedClean`. Сейчас там «Комментариев нет».

Показываем первую подходящую причину сверху вниз:

| Условие | Текст |
|---|---|
| Фоновое ревью выключено (`model.isPaused`) | Фоновое ревью выключено. Запустить можно по значку модели |
| Фоновое ревью репозитория выключено (`repo.isPaused`) | Фоновое ревью репозитория выключено. Запустить можно по значку модели |
| Черновик (`pr.draft`) | Черновик — фоновое ревью черновики пропускает. Запустить можно по значку модели |
| Ветка вне шаблона (`!isTaskBranch`) | Ветка вне шаблона веток задач — фоновое ревью её пропускает. Запустить можно по значку модели |
| Фоновых моделей нет: все модели только для ручного запуска | Все модели запускаются только вручную — фоновое ревью этот PR не возьмёт. Запустить можно по значку модели |
| Ни одна фоновая модель сейчас недоступна: у всех лимит исчерпан | Все фоновые модели упёрлись в лимит. Ревью будет после сброса |
| Идёт проход (`model.isRunning`) | Ревью ещё не было: идёт проход |
| Иначе | Ревью ещё не было: ждёт прохода, следующий через N мин. Если осталось меньше минуты — «…следующий в течение минуты». Если время прохода неизвестно — «Ревью ещё не было: ждёт прохода» |

Если хотя бы одна фоновая модель уже проверила текущий коммит, а другие ещё нет, пишем последнюю строку таблицы. Подробности по каждой модели — у её значка.

## 2. Подсказка у значка модели

Где: `AgentIcons.swift`, `AgentReviewButton.hint`. Сейчас для `manualOnly` к подсказке дописывается «В фоне эта модель не запускается».

| Состояние значка | Особое состояние модели | Текст |
|---|---|---|
| нет ревью | только вручную | Cursor: ревью не было — модель только для ручного запуска. Нажмите, чтобы запустить |
| старый коммит | только вручную | Cursor: ревью было на старом коммите, в фоне модель не запускается. Нажмите, чтобы проверить новый |
| нет ревью или старый коммит | лимит исчерпан | Codex: лимит исчерпан до 14:00 — ревью будет после сброса |
| актуально | ревью пропущено, тот же патч после rebase | Claude: повторное ревью не нужно — после rebase изменения те же. Нажмите, чтобы проверить заново |
| актуально | ревью пропущено, только исключённые файлы | Claude: ревью не понадобилось — в диффе только исключённые файлы. Нажмите, чтобы проверить заново |
| актуально | ревью пропущено, пустой дифф | Claude: ревью не понадобилось — в PR нет изменений относительно целевой ветки. Нажмите, чтобы проверить заново |
| остальные | — | Как сейчас |

При лимите в подсказке нет «Нажмите, чтобы запустить»: запуск всё равно упрётся в лимит. Сама кнопка остаётся рабочей, потому что данные о лимите могут быть устаревшими (см. п. 7). На макете у лимита была фраза «Нажмите, чтобы запустить»; эта строка спецификации её заменяет.

Если у модели одновременно лимит и «только вручную», показываем лимит: он временный и касается и ручного запуска.

## 3. Заголовок секции репозитория

Где: `OverviewView.swift`, `repoSection`, после `Text("· \(snapshot.prs.count)")`.

Если у репозитория выключено фоновое ревью (`repo.isPaused`) и общее фоновое ревью включено, показываем:

```
BACKEND · 1  ⏸ фоновое ревью выключено                обновлено 2 мин назад
```

- `HStack(spacing: 4)`: `Image(systemName: "pause.circle.fill")` оранжевым (`Color.orange`) и `Text("фоновое ревью выключено")`.
- Шрифт и цвет — как у остального заголовка (11 pt medium, `.secondary`). `.textCase(nil)`, как у «обновлено…», чтобы текст не ушёл в капслок.
- Подсказка: «Фоновое ревью этого репозитория выключено в настройках. Ручной запуск по значку модели работает».

Когда выключено общее фоновое ревью, пометку в секциях не ставим: об этом уже говорит шапка обзора.

## 4. Капсулы в шапке обзора

Где: `OverviewView.swift`, `statusBar`, после `Spacer()`, перед кнопками ▶ / ■ и ↻.

```
● Ожидание · следующая проверка через 12 мин   [🕒Codex: лимит до 14:00] [⏸Cursor: только вручную]  ▶ ↻
```

Одна капсула на каждую модель в особом состоянии. Порядок: сначала лимит, потом «только вручную»; внутри группы — в порядке `model.agentIds`.

Вид капсулы:
- `HStack(spacing: 4)`: значок модели с тем же бейджем, что в строках (п. 5), в кадре 16×16 (значок 15 pt с бейджем, масштаб 0.8), затем текст;
- текст 11 pt semibold;
- отступы: по горизонтали 7, по вертикали 3; форма `Capsule()`;
- лимит: текст `Color.red`, фон `Color.red.opacity(0.12)`;
- только вручную: текст `.secondary`, фон `Color.secondary.opacity(0.14)`, как у `Tag`.

Тексты:
- лимит: «Codex: лимит до 14:00». Время сброса: сегодня — «до 14:00»; завтра — «до завтра 14:00»; позже — «до 31 окт.»;
- только вручную: «Cursor: только вручную».

Подсказки:
- лимит: «Codex исчерпал лимит, сброс 31 октября в 14:00. После сброса модель снова начнёт ревью сама. Обновлено N мин назад»;
- только вручную: «Cursor не участвует в фоновом ревью и запускается только по клику на значок. Включить — Настройки → Модели».

Клик по капсуле открывает «Настройки» на секции «Модели» — тот же переход, что `openRepos`, плюс прокрутка к моделям, если она уже есть. Если прокрутки нет, достаточно открыть «Настройки».

Когда выключено общее фоновое ревью, капсулы «только вручную» не показываем: в этот момент вручную работают все модели. Капсулы лимита остаются.

Если строка статуса длинная, она по-прежнему обрезается (`lineLimit(1)`); капсулы не сжимаются (`fixedSize()`).

Дополнение после проверки qa. При выключенном фоновом ревью и двух капсулах статус обрезался до «Фоновое ревью выключено, работ…». Поэтому:
- при выключенном фоновом ревью текст статуса — коротко «Фоновое ревью выключено»;
- прежний полный текст «Фоновое ревью выключено, работают только запуски по иконкам» уходит в подсказку `.help` на статусе;
- кнопка «Включить» рядом остаётся.

Капсулы не сокращаем: время сброса в них — главное.

## 5. Бейдж на значке модели

Где: `AgentIcons.swift`, `AgentReviewButton`: оверлей поверх `AgentMark` в кадре 15×15.

- Лимит: `Image(systemName: "hourglass.circle.fill")`, цвета `.white` и `Color.red` (палитра).
- Только вручную: `Image(systemName: "pause.circle.fill")`, цвета `.white` и `Color.gray`.
- Размер 8 pt bold. Подложка `Circle().fill(Theme.card).padding(-1)`, чтобы бейдж отделялся от знака. `overlay(alignment: .bottomTrailing)`, сдвиг `offset(x: 3, y: 3)`.
- Цвет и прозрачность самого значка не меняются: по-прежнему видно, было ли у модели ревью (серый / приглушённый / полный цвет).
- Во время ревью (вращение) бейдж не показываем.
- В секции репозитория с выключенным фоновым ревью и при выключенном общем фоновом ревью бейдж «только вручную» не показываем. Бейдж лимита показываем всегда.

Зона клика остаётся 20×20, бейдж в неё входит.

## 6. Подсказка у зелёной галочки

Где: `OverviewView.swift`, `threadsCounter`, ветка `reviewedClean`.

Если хотя бы одна фоновая модель отметила текущий коммит пропуском без ревью (п. 7, причины `ignored` или `empty`):
- `ignored`: «Ревью не понадобилось: в диффе только исключённые файлы»;
- `empty`: «Ревью не понадобилось: в PR нет изменений относительно целевой ветки».

Пропуск `rebase` (тот же патч, что на прошлом ревью) подсказку не меняет: изменения действительно проверены раньше, остаётся «Модели проверили последний коммит и замечаний не нашли».

Почему это нужно: при пропуске сервис записывает голову как проверенную (`src/review.mjs:362–365`), поэтому у такого PR без комментариев сейчас появляется галочка «Модели проверили…», хотя модели его не читали.

## 7. Какие данные окну нужны от сервиса

### Причина пропуска

Сейчас причина пишется только в `skips.jsonl` (`src/review.mjs:377`), без коммита. Окну нужно знать её для текущей головы PR и каждой модели.

Предложение: в состоянии PR рядом с `reviewed` и `patch` хранить, что голова отмечена пропуском, например `skipped[agent] = { head, reason }`, где `reason` — `rebase` / `ignored` / `empty`. Запись снимается, когда модель делает настоящее ревью. Формат — на усмотрение dev; окну достаточно ответа на вопрос «текущая голова у этой модели отмечена пропуском, и по какой причине».

### Лимит модели

Уже есть: `limits.json` — `usedPercent`, `resetsAt`, `at` (`src/limits.mjs`, `AgentLimit` в `Model.swift:860`).

Модель считается упёршейся в лимит, если `usedPercent >= 100` и `resetsAt` ещё не наступил. Во всех остальных случаях лимит **неизвестен**: ни бейджа, ни капсулы, ни лимитной подсказки, модель выглядит как обычно.

Свежесть данных (`at`) для этого условия не важна: исчерпанный лимит до сброса сам не восстанавливается. Правка 30.10.2026 после BUG-028: раньше здесь было ещё «`at` не старше 1 часа». Из-за него бейдж Claude пропадал через час после последнего ревью, хотя лимит оставался исчерпанным. У Claude отдельного опроса лимита нет, данные обновляются только при его ревью.

### Зависимость от BUG-028

BUG-028 исправлен (7224c53). Раньше устаревший лимит Cursor хранился с прошедшей датой сброса. Проверка `resetsAt` это закрывает: если сброс прошёл, лимит неизвестен и бейджа нет. Ложного «лимит до …» не будет.

## 8. Задел на порог лимита (в эту задачу не входит)

В бэклоге есть несогласованная идея «порог 20 %: модель выходит из фонового ревью». Сейчас бейдж с песочными часами значит только «лимит исчерпан». Чтобы порог потом добавился без переделки, особое состояние модели держать одним перечислением, а не флагами, например:

```swift
enum AgentAvailability { case available, limitExhausted(resetsAt: Date), manualOnly }
```

Бейдж, капсула и подсказки строятся из этого значения. Порог позже станет ещё одним случаем, например `limitThreshold(remaining:resetsAt:)`. У него будут те же песочные часы, другой цвет (оранжевый) и текст «Codex: осталось 18 % — вне фона до …».
