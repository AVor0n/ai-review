# Спецификация: лист «Тестирование PR» в приложении Tauri (B-30, экран 5 из 8)

Дата: 26.11.2026, дизайнер. Одобрено пользователем 26.11.2026 («Одобряю»).
Макет: `product/design/mockups/2026-11-26-tauri-qa.html`.
Источник поведения: `menubar/QaViews.swift` (`QaSheet`, `QaText`, `QaMediaWindow`, `QaMediaBrowser`, `QaThumbnail`).

## Главное

Лист переносится без изменений: вкладки «План» и «Отчёт», окно просмотра скриншотов и видео. Тексты — слово в слово из SwiftUI. Действия — те же команды через API сервиса:
- план;
- прогон с `skip`, `extra`, `note`;
- остановка;
- копирование плана и отчёта;
- сохранение тестов (`qa save`).

Разметка — шаблоны `tpl-sheet-*`, `tpl-qa-*`, `tpl-report-body` макета. Лист — общий `.sheet` с модификаторами:
- `.sheet--large` — ширина 700;
- `.sheet--tall`.

«Ход прогона» — классы `.step` из доработки (B-34). Строки опасных мест, «Не проверить» и тестов — `.place`.

Новое в `product/design/web`:
- токен `--indigo` — тег уровня кейса;
- классы `.checkbox`, `.tags`, `.qa-case*`, `.labeled*`, `.bug-box`, `.code-box`, `.gallery`, `.thumb*`, `.status-grid*`, `.card-pad`, `.save-row*`, `.banner__message`, `.sheet__note`, `.viewer*`;
- иконки `i-qa-failed`, `i-qa-blocked`, `i-qa-unconfirmed`, `i-bug-fill`, `i-file-text`, `i-eye-slash`, `i-play-circle-fill`, `i-image`, `i-chevron-left`, `i-check`.

## Что меняется по сравнению с SwiftUI

1. **Лист поверх поповера** на «Обзоре». Ширина 700, высота — вся высота поповера; в SwiftUI было 560. Заглушка «Тестирование PR» из первой поставки убирается.
2. **Чекбоксы кейсов** — свой `.checkbox`: скруглённый квадрат 14, отмеченный акцентный с белой галочкой. Системный чекбокс Mac на Windows выглядел бы чужим.
3. **Подтверждение прогона** — системный диалог Tauri. Заголовок «Запустить прогон #N?», кнопки «Отмена» и «Запустить». Два текста из SwiftUI: с e2e и без. На Windows в тексте с e2e «Mac будет заметно нагружен» заменяется на «Компьютер будет заметно нагружен».
4. **Файлы на Windows.** Папка прогона, сохранённые тесты, скриншоты и видео лежат в WSL, поэтому открываются в Проводнике по пути `\\wsl.localhost\<дистрибутив>\…`. Кнопки «Открыть папку прогона», «Показать» и «Показать в Finder» → «Показать в Проводнике», «Открыть в Просмотре» → «Открыть в приложении по умолчанию».
5. **Окно просмотра** — отдельное окно Tauri, а не NSWindow. Поведение то же, см. ниже.

## Шапка и вкладки

- Заголовок «Тестирование #N», под ним название PR.
- Переключатель «План / Отчёт» (сегменты 80) — только когда есть и план, и отчёт.
- Справа крестик.

Вкладка при открытии — «Отчёт», если есть отчёт или прогон в очереди, идёт или упал; иначе «План». При смене состояния вкладка переключается сама:
- очередь прогона, прогон, готово, ошибка → «Отчёт»;
- очередь плана, план, план готов, план упал → «План».

## Строка статуса

| Состояние | Значок | Текст |
|---|---|---|
| План или прогон в очереди | `i-clock`, вторичный | «План в очереди» / «Прогон в очереди», вторичным |
| Составляется план, идёт прогон | `i-hourglass` `.hourglass`, `--blue` | «Составляется план · 2 мин 10 с» / шаг прогона · время. Под ним активность моноширинным, но у прогона — только пока шагов ещё нет |
| План готов | `i-check-circle-fill`, `--accent` | «План готов: 7 кейсов. Снимите лишние и запустите прогон» |
| Прогон готов | `i-seal-check-fill`, цвет итога | «Прогон готов, найдены ошибки» / «Прогон готов, все кейсы прошли» / «Прогон готов» |
| Ошибка | `i-warning-fill`, `--orange` | «План не удался» / «Прогон не удался» оранжевым |

Цвет итога:
- `--red`, если есть ошибка приложения;
- `--orange`, если есть неподтверждённые или непроверенные кейсы;
- иначе `--green`.

Ошибка сервиса — под статусом `.banner--alert` с `.banner__message` целиком. Многострочная — с `--mono`.

## Вкладка «План»

Порядок:
1. Баннеры `.banner--warning`, если нужны:
   - «План устарел» — план на другом коммите, чем PR, иконка `i-history`;
   - «Проверять нечего» — иконка `i-eye-slash`.
2. «Суть · <вид>»: Исправление ошибки / Новая функциональность / Переделка без изменения поведения / Другое.
3. «Как должно работать».
4. «Опасные места · N» — `.place`: `i-warning` оранжевым, путь моноширинным с многоточием посередине.
5. «Кейсы · M из N» — строки `.qa-case`.
6. «Свои кейсы» — `.text-field--multiline` высотой 64 на фоне `--bg`. Каждая строка — кейс.
7. «Не проверить · N» — `.place` с `i-eye-slash`.
8. «Подробности»: Коммит плана, Составлен, Цена плана.
9. «На что обратить внимание»: поле и кнопка «Составить план» / «Составить план заново». Во время плана или прогона кнопка неактивна.

Плана нет и он не составляется — только пункт 9. План составляется — текст «Claude читает дифф, описание, комментарии ревью и e2e-тесты репозитория. Обычно несколько минут.»

### Строка кейса

- Чекбокс: отмечен — кейс идёт в прогон. Пока идёт план или прогон, чекбоксы неактивны. Снятый кейс `.qa-case--off` — 50 %.
- Заголовок: id (`C1`) вторичным, название medium, теги, шеврон.
- Теги (`.tags`):

  | Тег | Значения | Цвет |
  |---|---|---|
  | уровень | юнит / компонентный / e2e | `--indigo` |
  | источник | ваш / изменение / регрессия | «ваш» `--accent`, остальные серые |
  | важность | важный / средний / низкий | «важный» оранжевый, остальные серые |

- Свёрнутый кейс: под заголовком «ожидается» вторичным, не больше двух строк.
- Клик по строке (кроме чекбокса) раскрывает кейс `.qa-case--expanded`: шеврон поворачивается, анимация 150 мс. Видны блоки `.labeled`:
  - «Проверяемый файл»;
  - «Данные»;
  - «Шаги» — нумерованный список;
  - «Ожидается».

Сноска под кейсами: «Снятые кейсы не проверяются. Нажмите на кейс, чтобы увидеть данные и шаги.» Кейсов нет — «Кейсов нет».

## Вкладка «Отчёт»

Порядок:
1. «Ход прогона» (`.step`) — пока прогон идёт или упал.
2. Ошибка прогона.
3. Если отчёт прошлый, а сейчас идёт новый прогон, — «Ниже — отчёт прошлого прогона» (`.sheet__note`). Прогон в очереди и отчёта нет — «Прогон начнётся, когда освободится очередь тестирования.»
4. Баннеры `.banner--warning`:
   - «План и прогон на разных коммитах»;
   - «Отчёт устарел».
5. «Итог»: текст модели и `.status-grid` — значок, число и статус по порядку «Ошибка приложения, Не подтверждено, Не удалось проверить, Прошёл, Пропущен». Нулевые не показываются.
6. «Окружение» — если модель написала проблемы окружения.
7. «Кейсы · N» — `.qa-case--result`:
   - слева значок статуса 14:

     | Статус | Значок | Цвет |
     |---|---|---|
     | Ошибка приложения | `i-qa-failed` | `--red` |
     | Не подтверждено | `i-qa-unconfirmed` | `--yellow` |
     | Не удалось проверить | `i-qa-blocked` | `--orange` |
     | Прошёл | `i-check-circle-fill` | `--green` |
     | Пропущен | `i-minus-circle-fill` | серый |

   - под заголовком название статуса цветом статуса; жёлтый заменяется основным;
   - «Тест» — путь;
   - «Проверено»;
   - баг — `.bug-box` с `i-bug-fill`;
   - «Заметки»;
   - у неподтверждённого — «Модель сообщила «…», а итоговый прогон Playwright — «…».»;
   - «Ошибки Playwright» — `.code-box`;
   - галерея `.gallery`: 4 превью 16:9, PNG уменьшенный до 480 px, у видео `.thumb__video` «Видео». Клик открывает окно просмотра на этом файле, подсказка — имя файла.
8. «Тесты · N»:
   - строки с `i-file-text`: путь моноширинным, «уровень · кейсы»;
   - внизу `.save-row`: «Ещё не сохранены» и «Сохранить в <repo>». После сохранения — значок `i-check-circle-fill`, «Сохранены 2 минуты назад в <repo> · ветка <ветка>», строки о переименованных файлах и предупреждение оранжевым о другой ветке, кнопки «Сохранить снова» и «Показать»;
   - во время сохранения — `.spinner`, кнопки неактивны;
   - сноска из SwiftUI.
9. «Подробности»: Фронтенд, Бэкенд, Снят, Цена и время, Папка прогона.

## Кнопки внизу

Слева:
- «Открыть PR»;
- «Скопировать план» / «Скопировать отчёт» — по вкладке. После копирования на 2 с «Скопировано». Без плана или отчёта неактивна;
- на «Отчёте» — «Открыть папку прогона».

Справа:

| Состояние | Кнопка |
|---|---|
| Очередь, план, прогон | «Прервать», `.button--destructive` |
| Вкладка «Отчёт» | «Новый прогон…» — переключает на «План» |
| Вкладка «План», план есть | «Запустить прогон…», `--prominent`. Неактивна без выбранных и своих кейсов. Подсказка по уровням: с e2e — «30–60 минут и несколько долларов: сборка бэкенда в Docker, отдельное e2e-окружение, тесты по выбранным кейсам», без — «Юнит и компонентные тесты на Vitest, без Docker и браузера» |

## Окно просмотра

Отдельное окно Tauri:
- **Размер.** 85 % экрана, кадр 16:9 плюс панель 52 снизу, по центру экрана, на котором открыт поповер. Минимум 480×320.
- **Поверх поповера.** Открывается выше поповера и не закрывает его. Когда поповер закрыт, окно перестаёт быть поверх чужих окон.
- **Заголовок:** «имя файла — 2 из 4».
- **Картинка** вписана в окно; щипок или двойной клик — масштаб, двойной клик ещё раз — снова по размеру окна.
- **Видео** проигрывается сразу. Скорость — сегменты «0,5× / 1× / 1,5× / 2×» по 48 px, общая для всех видео. Закрытие окна останавливает видео.
- **Панель** `.viewer__bar`:
  - стрелки «назад / вперёд» `.square-button` с `i-chevron-left` и `i-chevron-right`, на краях списка неактивны;
  - подсказка «Щипок или двойной клик — увеличить» или скорость;
  - справа «Показать в Finder», «Открыть в Просмотре» (у видео — «Открыть в другом приложении»), «Закрыть». На Windows — названия из раздела «Что меняется».

## Windows

Рамка поповера из первой поставки, лист тот же. Проверить:
- пути из WSL открываются в Проводнике;
- скриншоты и видео из WSL грузятся в превью и в окно просмотра;
- `.webm` играет в WebView2.

## Готово, когда

- Лист на Mac в светлой и тёмной теме совпадает с макетом, на Windows — то же содержимое. Проверка — скриншот рядом со страницей макета.
- На реальном сервисе работают:
  - план;
  - выбор кейсов и свои кейсы;
  - прогон с e2e и без;
  - ход прогона;
  - отчёт с багами, ошибками Playwright и медиа;
  - сохранение тестов;
  - копирование;
  - «Прервать»;
  - окно просмотра с картинками и видео.
- Пробирка в строке PR открывает лист вместо заглушки.
