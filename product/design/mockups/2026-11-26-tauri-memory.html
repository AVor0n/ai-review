Память ревьюеров в приложении Tauri

одобрено 26.11.2026 26.11.2026 · дизайнер · задача B-30, экран 2 из 8

Лист памяти переносится из SwiftUI без изменений. Остаются три вкладки — «Правила», «Разбор», «Что менялось», — правка и удаление правил, своё правило снизу, разбор с планом «было / станет», журнал с откатом и пустое состояние «Изучить историю». Вёрстка — HTML/CSS на product/design/web.

Что меняется по сравнению с SwiftUI. (1) Лист открывается прямо поверх поповера, на той вкладке, где была кнопка. В SwiftUI окно сначала переключалось на «Настройки», потому что лист жил там. Здесь «Настройки» ещё не перенесены. (2) Подтверждение отката — системный диалог, как подтверждения в поповере. (3) Справа от вкладок больше нет подписи «Срабатывания считаются с … · ревью с учётом: N» — по решению пользователя; счётчик срабатываний у каждого правила остаётся. (4) Иконки — Phosphor. (5) На Windows файл памяти лежит в WSL. Кнопка «Открыть в VS Code» открывает его через путь \\wsl.localhost\…; если VS Code не установлен, кнопки нет. Больше ничего не меняется, тексты слово в слово.

1. Открытие из баннера

«Проверить правила» в баннере переполненной памяти или «Посмотреть» в баннере новых правил. Поповер приглушается, лист 600 px встаёт сверху по центру. Закрывается крестиком или кликом по приглушённому фону. Изменения сохраняются сразу, поэтому кнопки «Готово» нет.

Синяя точка — новое правило. Точки гаснут, когда лист закрыли: пока он открыт, они помогают найти новое. На «Разборе» — число изменений в готовом плане; оно видно, пока открыта другая вкладка. Ссылка «из ревью PR #…» открывает PR в браузере.

2. Вкладка «Разбор»

Модель предлагает план, человек смотрит его и применяет. Пока план не применён, память не меняется.

План готов

В «было» красным подсвечено то, чего не осталось, в «станет» зелёным — что появилось. Пробел между двумя изменёнными словами тоже подсвечен, чтобы правка читалась одним куском. «Отказаться» удаляет план, память остаётся как есть. Подсказка у «Применить» — «Склеить, переписать и удалить правила по плану. Применённый разбор можно откатить: pr-reviewer memory restore frontend».

До разбора

Идёт разбор

Время идёт каждую секунду, часы переворачиваются. Лист можно закрыть — разбор продолжится.

План устарел

План применён

Последняя строка вывода сервиса. Если разбор не удался — карточка «Не получилось» с текстом ошибки моноширинным.

3. Вкладка «Что менялось»

Журнал памяти от новых записей к старым, последние 100. Дата точная: журнал читают по датам. Откатить можно только последний применённый разбор.

Откатить разбор памяти?

Память вернётся к копии, сохранённой перед разбором: удалённые правила вернутся, переписанные и склеенные — станут прежними. Если после разбора память менялась, сервис откажет, чтобы не потерять эти изменения.

ОтменаОткатить

Подтверждение отката — системный диалог Tauri. После отката над журналом строка «Разбор откачен: правил было 59, стало 67».

4. Правка правила, пустая и повреждённая память

Правка правила

Карандаш превращает строку в поле на несколько строк с «Отмена» и «Сохранить». Удаление — корзина, без подтверждения, как в SwiftUI.

Памяти ещё нет

Файл повреждён

Поле своего правила неактивно: в повреждённый файл сервис не пишет.
